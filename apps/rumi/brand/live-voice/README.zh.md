# Live Voice

[English](README.md) | 中文

Rumi 的全双工语音功能：GPT-Live 负责听和说，Harness 执行它委派的工作。

该软件包由 Rumi 维护，名称为 `@rumi/live-voice`。`src/` 管理 OpenAI 连接和 Harness 委派；`client/` 管理麦克风采集、播放和输入框旁的控件。Rumi 在默认配置中包含此 Bundle。

## 配置

在 **插件 → Live Voice** 中设置密钥。主机通过 `ctx.credentials` 保存密钥；设置响应仅包含是否已配置、掩码提示和存储位置。凭据服务的解析结果优先于显式配置和指定的旧密钥文件（内置配置使用 `~/.rumi/live-voice.key`）。启动环境是最后的回退来源。保存替代密钥不会改写旧文件。

## 会话生命周期

语音控件固定在发送按钮旁，麦克风静音控件出现在它的左侧。语音启用时，图标的前景色与背景色互换；动画也会指示活动状态。

连接期间，控件显示虚线加载环，并可再次点击取消。主机报告就绪且本地音频设置完成后，才会显示启用配色和静音控件。

关闭语音会丢弃尚未提交的委派并立即停止本地采集。已提交给 Harness 的工作可以继续完成；插件释放会等待其会话写入和传输关闭。正在启动的连接不能在插件释放后发布会话，同一对话的重叠启动请求会被拒绝。

委派保留缓冲的完整请求，包括单词指令和中文指令。转录缓冲区最多保留 4,000 个字符。重复的委派 ID 会被忽略；新委派可以使用相同的话语。

## 上下文

输入框提供所属会话的 ID。连接前，主机解析该会话并加入其规范对话内容：用户文本、助手文本和保留的压缩摘要。`contextMaxCharacters` 默认保留最近 16,000 个字符（可配置为 1 到 64,000）；省略的早期文本会被标记。系统提示、推理块、工具载荷和非文本附件不包含在内。源文本可从会话日志重建。

同一会话中新提交的消息会作为静默上下文转发，包括连接握手期间收到的消息。其他会话的更新会被忽略。输入框切换到另一会话时，会停止语音并重置控件。语音无法直接查看预览器或项目文件；它会将这些问题委派给 Harness。

主机管理委派 ID 和通道选择。其他插件通过 `ctx.liveVoice` 提供启动指令：

```js
ctx.inject(['liveVoice'], (scoped) => {
  scoped.effect(() => scoped.liveVoice.register({
    id: 'project',
    instructions: sessionId => readProjectInstructions(sessionId),
  }), 'context')
})
```

各项贡献在会话启动时按 `order` 组合。抛出异常的贡献会被记录并跳过。`@rumi/projects` 通过此方式提供项目的 `AGENTS.md`。对此文件的修改在下一次语音会话中生效。

Harness 轮次运行期间，主机跟踪会话事件，每隔几秒最多发送一次静默的 `thinking` 说明。新委派在 agent 的下一个步骤加入当前工作，不等待下一轮。按序提交共享一个运行区间；最终结果以最新委派的 commentary 返回，不分别归因于每次纠正。已经执行的命令不会被中断。

## 验证

运行 `pnpm exec vitest run --config apps/rumi/vitest.voice.config.ts`。此配置将直接发布的 JavaScript 导入解析到工作区源码。测试使用本地 WebSocket 服务器和可控的浏览器音频 Promise，不会联系 OpenAI 或采集麦克风音频。

贡献者还可以实现 `captureRequest({sessionId, requestedAt, signal})`，返回单独记录的 `rumi-voice-reference` 上下文消息的内容块。引用记录用户语音消息 ID，并在同一个下一步收件箱中紧接用户消息之前提交；语音气泡只包含转录的话语。标准上下文界面单独呈现引用，语音对话上下文不包含它。捕获从上次委派后的第一个非空转录片段开始，带时间戳的结果保留至委派。Print Studio 通过此方式提供指针图像与区域。捕获失败会明确记录为视觉上下文不可用，不会替换为旧捕获。关闭语音会中止待处理捕获。

语音指令要求高亮所提及的模型部位并用简单语言解释。明确请求、撤销请求和已提供的选项按上下文处理；意图不明确时需要澄清。简短回复和纠正必须委派给 Harness。不要求特定确认短语。

## 委派证据

收到委派时，主机立即发送静默 thinking 更新，以抑制待发送的自动确认。`acknowledgementDelayMs` 默认 800 毫秒；它不会停止已经生成的语音或模型独立发言。语音指令禁止在主机确认前声称请求已接收，也禁止在工具返回 `rendered` 前声称高亮已显示。

过早到达的委派会等待非空转录文字，最多等待 `transcriptWaitMs`（默认 5,000 毫秒），不会直接丢弃。重复 ID 不会重复提交。转录片段不一定是完整话语，含糊请求仍需澄清。文字未到达会明确报告失败。主机等待 agent 解析和引用捕获的期限为 `handoffTimeoutMs`（默认 10,000 毫秒）；超时后才完成的操作不会提交。关闭语音会取消文字等待并阻止未提交工作开始。

语音控件区分尚未发送、正在发送、已接收和失败。已接收只表示进入建模 agent 的收件箱，不表示工作完成。这些标签依据主机事件，不依据语音承诺。失败时请用户重复请求；不会自动重试，以免重复编辑。

`diagnosticsDirectory` 默认为 `~/.rumi/voice-logs`。每个实时连接写入以连接 ID 命名的私有 JSONL 文件，记录对话和连接 ID、时间戳、输入与输出转录片段、委派元数据、主机更新、接收或失败状态以及关闭原因。不记录音频或凭据。这些诊断日志与聊天消息分开，重启后保留，直到被删除。日志创建失败会阻止启动；写入失败会停止语音并报告错误。常规对话日志仍记录建模 agent 输入、工具以及高亮渲染结果。

贡献者可以实现 `refineRequest({sessionId, text, content, signal})`，在委派前根据累积转录片段细化已捕获内容。该钩子返回替换内容块，在捕获后按顺序运行，并共享语音取消信号。Print Studio 用它处理非破坏性的光标选择短语，无需额外模型请求。最终引用仍与用户话语分开记录；细化失败会添加明确的不可用上下文。

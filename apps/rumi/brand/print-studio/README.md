# Print Studio

English | [中文](README.zh.md)

Setup detection and guided Bambu Lab configuration for Rumi's 3D print workflow.

This slice covers setup plus a real test print. It answers three setup questions and adds one end-to-end print path:

- Is Bambu Studio installed?
- Does it have the H2D profiles?
- Is a printer configured and reachable on the LAN?

The host half discovers the printer over SSDP, exposes `GET /api/print-studio/status`, the Bambu Cloud routes under `/api/print-studio/cloud/*`, the mesh viewer routes under `/api/print-studio/viewer/*`, and the model-facing tools. Signing in fetches the bound printer's `dev_access_code`; Bambu Connect sends the sliced job. The browser half is the Print Studio card under **Plugins → Built-in plugin settings**, plus the 3D preview tab. The bundled [setup skill](skills/print-studio-setup/SKILL.md) and [FDM design skill](skills/fdm-design/SKILL.md) are registered at plugin load for agent discovery. They provide setup guidance and design constraints; the agent loads their instructions when relevant.

Printer IP and serial are stored in `$DSH_HOME/print-studio/printer.json` (owner-only). The LAN access code is stored through `ctx.credentials` as `BAMBU_LAN_ACCESS_CODE`; it is never returned to the client and never belongs in the profile patch.

The [printer-awareness skill](skills/printer-awareness/SKILL.md) connects live status tools and installed machine profiles to printer-specific decisions, preserving unknown readings and requiring a sourced build envelope.

## Test print

`POST /api/print-studio/print/test` (and the `print_studio_print_test` tool) slices the bundled 10 x 10 x 1.2 mm tile with Bambu Studio, sets the H2D dual-extruder project and the Supertack plate, and hands the sliced 3MF to Bambu Connect. Bambu Connect requires an adult to press **Send**; there is no supported API for that final authorization on macOS. `GET /api/print-studio/print/status` and `print_studio_progress` read progress, layers, temperatures, AMS, and errors over local MQTT.

The test tile is about six minutes.

## Mesh preview

Model previews display through one USD loading path in Three.js. Imported STL triangles are converted to USD; Blender publishes `model.usda`. Editable `.blend` originals remain separate. USD Physics joints and Isaac robot annotations describe the same meshes used for display and validation. Movement controls transform the loaded assembly without rebuilding geometry.

The `viewer/` module is a general 3D viewport for any conversation; printing is one caller, not its subject. One folder is one Cordis plugin, so it ships here rather than as a package of its own.

The STL scene document separates geometry from placement:

- a **datablock** is one mesh: the geometry the host read, its canonical STL bytes, and the
  centre its rotation turns around;
- an **object** places one datablock with a scale, a rotation, and a position; scale and
  rotation turn the mesh about its centre, and the position says where its bottom centre
  sits, so a part that grows or turns stays on the plate
- the **scene** is the objects plus the build volume they are checked against.

Opening the same file twice places two objects that share one datablock, so the browser fetches the geometry once and every placement moves without touching it.

Every change is a command (`addObject`, `removeObject`, `setTransform`, `setVisible`, `setVolume`), and commands return a new document, so undo is a list of earlier documents. The agent issues them through `mesh_open`, `mesh_transform`, and `mesh_remove`, and reads the result with the `meshState` runtime context; a gizmo, when there is one, will issue the same commands.

`GET /api/print-studio/viewer/state?sessionId=…` returns the scene as the browser draws it (one placement matrix per object, statuses, and counts). `GET /api/print-studio/viewer/model?sessionId=…&datablockId=…` returns one datablock's bytes, which never change once opened and are cached as immutable.

`bake.js` is the projection onto files: one mesh per visible object, transforms applied. It uses the same placement calculation as measurement. Export and slicing can consume these meshes without altering their source files.

STL imports accept files up to 20 MiB and 200,000 triangles. Editable designs use the [Three.js model interface](#editable-threejs-models). Scenes and datablocks are held in memory for eight conversations and disappear when the plugin unloads. An STL opened from a conversation renders through the same tab type as a file preview.

Only `viewport/` imports Three.js. Both model types use `transform.js` for placement; `bake.js` prepares placed STL geometry for export.

This is the one Cordis row that ships a renderer, so its browser half is bundled rather than served as plain JavaScript: Three.js stays private to this row and never enters the shared client module table. `esbuild` and `three` are development dependencies of `apps/rumi`; `build-client.mjs` writes `lib/client.js` and Three's license beside it.

## Account sign-in

The settings card opens Bambu's hosted sign-in page in an isolated Rumi desktop window. The desktop adapter accepts login messages only from that window's main frame on `https://bambulab.com`. Social sign-in opens the system browser and returns through a temporary loopback listener. Closing the window, closing Rumi, or reaching the three-minute deadline removes the listener and message handler.

The window advertises a space-delimited `BBL-Slicer/v02.08.02.61` user-agent marker so Bambu's page enables its Studio ticket callback. The page obtains an `http://localhost:<port>` address through `get_localhost_url` before opening the system browser; Bambu rejects numeric loopback addresses. Browser sign-in must retain that return address. Receiving a ticket closes the login window and focuses Rumi.

Print Studio validates the returned message, exchanges tickets through Bambu's ticket endpoint, and stores credentials through `ctx.credentials`. The desktop adapter retains neither tokens nor passwords. The browser card requires Rumi's desktop bridge; standalone DSH Web cannot open this native login window.

The hosted page and ticket exchange were verified with a live Bambu account; re-run that check after Bambu changes the page. Local tests cover the user-agent format, callback address, ticket delivery, window cleanup, message validation, and ticket requests.

## Source ownership

The host and client entrypoints, discovery, cloud protocol, native login window, sandboxed Bambu preload, mesh viewer, and behavior tests live in this package. `desktop/` is compiled separately for Electron by `tsconfig.desktop.json`; it is not imported by the Cordis host. Rumi composes this adapter through a private package import and bundles its preload. The app retains only the validated IPC entry, main-window ownership, and preload exposure. `apps/rumi/tests/print-studio.spec.ts` includes the package-owned tests in upstream test discovery. Executable UUID assignment belongs to Rumi packaging because it affects every native capability.

## Blender editing and USD previews

New modeling and mesh edits use local Blender background Python scripts through the existing shell tool and its permissions. Packaged Rumi includes Blender under `Resources/runtime/blender`; app updates replace that runtime with the pinned release. `blender_status` uses it by default and reports a broken bundle rather than silently falling back to a separate installation. An explicit `blenderExecutable` overrides discovery. Development checkouts can use `blenderHome/tools/blender/Blender.app`, `/Applications/Blender.app`, or the user's Applications folder; `blenderHome` defaults to `DSH_RUMI_HOME` or `~/.rumi`. The bundled [blender-modeling skill](skills/blender-modeling/SKILL.md) owns the agent workflow; the status tool returns the installed export-helper path.

The helper saves immutable `.blend`, USD and measurement revisions under `models/<name>/revisions/`, then atomically replaces `model.usda`. Scripts run a full Blender process without opening its window. Canonical USD uses metres, Z up; Three.js converts it to millimetres, Z up for cursor snapshots, measurements and highlights. Blender edits must account for object transforms and divide viewer coordinates by 1,000. The helper retains modifiers in the editable original and applies them to the viewing export. Export failure leaves the previous preview intact; partial revision files remain available for diagnosis.

`viewer_load` accepts self-contained ASCII USD layers inside the project, limited to 64 MiB and 200,000 visible triangles. References, external assets, composition, variants and animation are rejected before any asset resolver runs. Publish meshes and embedded material values in one static layer. The viewer discovers `models/<name>/model.usda` before legacy entries and reloads completed exports after two identical polls. Immutable snapshot URLs preserve version identity for cursor capture and agent highlights. Invalid exports retain the last successful preview and report an error. These checks do not establish print readiness.

`viewer_load` selects the model and wakes the viewer and waits for feedback matching the displayed URL, revision, placement, and build volume. `load.status: ready` acknowledges a visible render; `design.report` contains its measurements and `design.parameters` includes declared defaults and saved values. Build and source failures return their error, while hidden viewers, timeout, replacement, cancellation, and disposal have distinct non-ready outcomes. Timeout does not imply an unsupported model. Selection remains applied when acknowledgment fails; do not infer rollback or print readiness. Configure `viewerLoadTimeoutMs` on the Print Studio row (default 8000 ms, range 1–25000 ms).

The modeling skill supplies [solid construction defaults](skills/blender-modeling/SKILL.md#solid-construction-defaults) before editing: closed solids, Exact booleans, separate mechanical parts, controlled finishing and selective remeshing. These are agent instructions, not enforced operation restrictions; geometry validation still checks the results.

`blender_status` also returns `joints`, the path of `blender/rumi_joints.py`: a millimetre modelling kit with cleaned Exact Booleans and joint recipes loaded from `blender/joints/*.py`. Each recipe adds the mating features to the two parts it is given and returns joint records; the kit's `publish` turns those records into the USD assembly. The [`joints` skill](skills/joints/SKILL.md) lists every recipe with the result its sample obtained from the real checks, and its `references/` cards give calls and options. Recipes are starting points for the agent, not a validated library: each was checked alone at its default size, joins held by friction, magnets or hardware stay unverified, and several captive joints read `excessive_penetration` slightly above the default limit. Run `Blender --background --factory-startup --python-exit-code 1 --python tests/blender-joints.py` from this package directory for the kit regression.

## Explicit validation tools

The agent follows the [modeling skill](skills/blender-modeling/SKILL.md#validate-a-finished-revision). `blender_status` writes the project's `.rumi/print-checks.json` from the plugin's validation settings. Every `publish` then checks the new revision in a separate Blender process and prints `RUMI_CHECKS <json>`: the Toolbox and clearance findings with a nonzero count, any assembly declaration error and the dimensions. A publish without that file prints `status: unavailable`, and a failed or timed-out check never reports a pass. Two tools remain: `validation_mechanics` takes a model `path`, runs any missing assembly, geometry and fit stage for the current revision, stops with that stage's findings when one has a blocking error, and otherwise runs Bullet; `validation_accept` takes the `path` and `fingerprint` that `validation_mechanics` returns. The fingerprint captures model identity, source bytes, placement, build volume and validator policy; changed sources or placements invalidate previous stage results, and unchanged completed stage results are reused. Findings appear in tool results and `meshState.validation`; unresolved findings remain visible in the viewer. Opening a project and ending a turn never launch checks or repair turns. `validationRepairAttempts` remains accepted for existing profiles but has no effect.

Assembly inspection checks declarations and persists required movement intent. Geometry runs Blender's Toolbox without clearance or Bullet. Fit checks clearance and configured printer volume and prepares the physical bodies. With no build volume, printer fit remains unchecked. Bullet requires assembly, geometry and fit results without blocking errors for the same revision and consumes the prepared bodies. The host runs these stages itself, so acceptance never rests on the agent's `publish` checks. Acceptance requires every preceding stage, complete passing mechanical coverage and preserved movement intent; it performs no simulation. Tool failures, cancellation and source changes cannot establish acceptance. Repairs are ordinary agent edits followed by another publish, not queued turns.

USD checks use immutable source snapshots with the complete parent hierarchy applied before conversion to millimetres. Legacy models require a renderer export, bounded by `validationTimeoutMs`; publish USD to avoid depending on an open viewer. Tool cancellation and shutdown kill and await children before releasing snapshots and routes. The viewer displays current models throughout checks. `validationStateDirectory` defaults to the Rumi home's `validation` directory and stores accepted originals and required movement intent atomically; unavailable or corrupt state blocks acceptance. Existing project files are not rewritten. Accepted snapshots remain recoverable after restart; explicit checks establish current acceptance again.

The pinned GPL-licensed 3D Print Toolbox source and license ship under `blender/object_print3d_utils/`; `UPSTREAM.json` identifies the source revision. The adapter checks manifoldness, winding, intersections, degeneracy, distortion, thickness, sharp edges, and overhangs. Geometry is measured in millimetres with positional welding at 0.001 mm. Configure `validation.minimumThicknessMm` (default 1), `degenerateThreshold` (0.000001, applied by Toolbox to both edge length and face area), `overhangDegrees` (45), `sharpDegrees` (160), and `distortionDegrees` (45). `validationTimeoutMs` defaults to 60000. These are screening thresholds, not calibrated printer tolerances. Thickness sampling and overhang findings require review; intended overlapping solids also require interpretation. For assemblies with two or more parts, `insufficient_clearance` is an error in both manufacturing modes when the surface gap between two distinct parts is below `validation.minimumClearanceMm` (default 0.2, range 0–2, 0 disables). Gaps are measured in placed millimetres for every part pair except pairs joined directly by a `fixed` connection; overlap reports 0, and `details.pairs` lists up to eight pairs with `gapMm`, smallest first. The measure is vertex-to-surface and can miss a pure edge-to-edge minimum; a pass does not certify a printable fit. Declared movement receives the additional checks below. Assembly, supports, material strength, and final slicer readiness are not certified. The viewer retains only input/preview-limit guards and dimension/envelope measurements.

Run `Blender --background --factory-startup --python-exit-code 1 --python tests/blender-validation.py` and `tests/blender-publish-checks.py` from this package directory for the real Toolbox and publish-time regressions. The session tests cover the mechanics tool running its prerequisite stages, revision caching, stale results, cancellation and failures. Packaging additionally dispatches both tools through the composed Host profile and project-isolation policy against real solid and moving-wheel fixtures, including Blender, Bullet, acceptance, cached results, cross-project denial, stale-revision rejection and a single recorded tool-calling turn. See [installed validation qualification](../../tests/README.md#validation-tool-qualification).

## Mechanical validation

Models use USD Physics rigid bodies, collision APIs and fixed, revolute or prismatic joints. The default prim applies `IsaacRobotAPI`; ordered `isaac:physics:robotLinks` and `isaac:physics:robotJoints` relationships enumerate every mesh and joint. Links apply `IsaacLinkAPI`, joints apply `IsaacJointAPI`, and the first link is the fixed test root. Standard body relationships, local frames and limits define expected movement; every link must connect to the root. Revolute limits use degrees and prismatic limits use metres. Frames must meet at the saved rest pose and moving axes must agree. Required finite ranges describe coverage, not physical end stops. `rumi:control`, `rumi:manufacturingMode`, `rumi:sequences` and `rumi:disassembly` carry Rumi-specific UI and manufacturing requirements. Recorded movement intent survives revisions and restarts; deleting a required control or narrowing its range cannot hide a failed check. See [physical movement declarations](skills/blender-modeling/SKILL.md#declare-physical-movement).

After Blender finds no blocking geometry errors, the host passes the evaluated physical meshes and assembly to the bundled Bullet helper using protocol 2. Double-precision GImpact contacts preserve concave geometry. Only the declared root is held; every other part, including retaining hardware, remains dynamic. Fixed, revolute and prismatic connections describe expected relative behavior without creating ideal joints. Generic probes challenge forbidden movement and force-drive permitted movement through sampled poses, monitoring every connection and collision pair. Retention tests escape, not tightness: a part may move through its play and passes when its connector geometry stops it within `mechanics.retentionTravelMm` (default 2, range 0.1–10) of pivot travel and `mechanics.retentionTiltDegrees` (default 15, range 1–45) of tilt. `unstable_at_rest` and `unretained_part` report a part that travels past either bound, or is still travelling outward when a retention probe ends. `linearToleranceMm` and `angularToleranceDegrees` decide only whether a driven joint reached its target (`movement_blocked`) and `movement_below_tolerance`. Reports record part, connection and sequence coverage and the resolved simulation policy. Errors return to the calling tool; unsupported physics and incomplete coverage remain unverified. Missing executables, timeouts and malformed reports cannot pass. `mechanics.maxTotalSteps` defaults to 2,000,000 (configurable from 1,000 to 10,000,000); exceeding it leaves assemblies unverified; baseline attachment checks still report defects before full movement is skipped.

Assemblies contain at most 128 physical parts and 128 connections. Grouping disconnected solids into one mesh does not supply a physical attachment. `publish(directory, configure_robot=callback)` gives the callback an OpenUSD stage for authoring standard declarations and retains their USD layer in the editable `.blend`; omitting the callback preserves saved declarations. Blender’s bundled OpenUSD authors the Isaac annotations directly, following NVIDIA’s [Kit-free schema approach](https://nvidia.github.io/simready-foundation/2026.07.1/features/FET_101_ISAAC.html). Isaac Sim is not required. These annotations describe intended behavior; Bullet probes whether the mesh geometry realizes it. Unsupported graph coupling, deformable connections and numerical uncertainty require review. A `separate` assembly without declared `rumi:disassembly` steps is verified by the probes alone; the removal route is checked only when those steps are declared, as translation-only reverse-assembly paths.

`bulletExecutable` selects an explicit development override; packaged Rumi uses its bundled helper without searching `PATH`. `mechanicsTimeoutMs` defaults to 600000 (ten minutes), independently limiting wall time. `mechanics.retentionWorkers` defaults to 4 (1–4): after baseline checks pass, independent retention loads run in bounded parallel batches with private collision shapes. Movement steps remain sequential; findings retain serial order and every connection is still monitored. Independent retention loads for every connection run at the saved pose and at each range-endpoint pose; intermediate movement samples and the return move probe only the moved connection. For sequences, every connection is probed at the last waypoint and only the driven connections at intermediate waypoints. No probes are omitted based on apparent symmetry or distance. Native reports are bounded to 8 MiB. Agent context and tool results count passing probes and retain all failed or inconclusive probes, coverage and policy; the viewer state retains full diagnostic reports. The `mechanics` profile configures density, force/torque limits, durations, integration, contact tolerance, gravity, friction and sampling. Defaults include gravity `[0,0,-9.81]` m/s², friction `0.2`, movement samples every 30 degrees or 2 mm, `probeDurationSeconds` 0.25, `maxPenetrationMm` 0.15, and removal-path samples every 0.2 mm. These are screening assumptions, not calibrated printer or material properties. A pass covers the reported finite probes; it does not certify continuous collision freedom, every simultaneous configuration, support removal, strength, wear, deformation or slicer readiness. `printReady` remains false.

## Persistent movement controls

Movement controls live at the viewer’s bottom-right, opposite cursor controls, independently of temporary edit controls. Control surfaces use inset highlights without outer shadows. Movement changes only the local preview pose and never modifies validation input. The panel remains visible but disabled during temporary edits. Reset the pose before requesting source-bound cursor edits; preview movement does not establish mechanical acceptance.

USD revolute and prismatic joints generate sliders, using `rumi:control` as the label when supplied and the child mesh name otherwise. The preview applies joint frames to each part and its descendants, including fixed attachments. Shared controls use the overlapping declared range and require matching units. Up to 12 independent controls are supported; malformed declarations, closed loops or unsupported bindings keep geometry visible and report `assembly_motion_unavailable` without offering misleading controls. Pose values survive reloads while the assembly description remains identical. Preview transforms borrow original mesh resources and never modify export geometry or imply mechanical acceptance.

## Editable Three.js models

Store each independent preview in `models/<name>/model.usda` and preserve editable Blender originals. The viewer renders USD through Three.js without executing project code. To migrate an existing GLB model, open its editable `.blend` or use the helper’s `import_mesh` on its GLB, then call `publish`. Legacy assembly declarations are converted to USD Physics joints once; subsequent edits retain the native USD description. Keep the original files. Legacy JavaScript entries must export their actual geometry through confined modeling tools. No project is migrated automatically.

`viewer_transform` applies uniform scale, XYZ rotation in degrees, and bottom-centre position in millimetres without changing source. `viewer_camera` frames the design from an azimuth and elevation without altering its geometry. Both operate on the loaded design as a whole; edit named parts in source. Camera state and placement survive successful rebuilds. Failed imports or builds leave the last successful model visible and show an error; the `meshState` runtime context includes the source revision, build error, and renderer-reported measurements. Measurements require the preview to be mounted and never certify print readiness. The existing STL import and scene tools remain available separately.

Each conversation owns its live preview. The last selected entry and plate dimensions are saved atomically in the project’s `.rumi-viewer.json` and restored when a preview opens after restart; without a saved selection, the first discovered model opens. Switching models refreshes the preview as soon as the host accepts the selection, without waiting for the periodic poll, and resets camera and placement. A missing or unreadable saved entry shows an error instead of substituting another model; select an available model to recover. Discovery excludes symlinked folders and entries. Only the selected source is loaded; other model files remain on disk. STL scene objects remain in memory.

Source loading and snapshots are Cordis effects owned by the Print Studio plugin. Snapshot effects collect the route registrations’ exact disposers. Unloading stops source polling, awaits admitted loads and polls, and releases routes; the viewer discards late imports and disposes its GPU resources. Tests exercise these paths with real Cordis contexts.

### Visual clarification

The bundled `clarify-mesh-changes` skill guides region identification and clarification of the requested operation. `viewer_highlight` replaces up to eight Gaussian ellipsoids on the editable model loaded with `viewer_load`; STL imports are not supported. Pass `design.path`, `design.revision`, and `design.url` from the `meshState` runtime context, a short `label`, and `blobs` containing three-number `center`, `radii`, and `rotationDegrees` arrays. Coordinates are model-local millimetres including part transforms, before whole-design placement; rotations are XYZ Euler degrees. Radii are nominal extents: influence is `exp(-1.5 * dot(q,q))` after inverse rotation and division by radii, combined by maximum and faded with `smoothstep(0.08,0.42,influence)`. Every intersected surface can be affected, including the back of a shell.

Agent regions use teal fill and dark wireframe; the cursor region uses blue fill and dark blue edges, blended with the shaded surface before tone mapping independently of the app theme. The viewport reveals triangle edges inside the soft region without changing source geometry, materials, measurements, exports, or project covers. Agent-proposed highlights are controlled through the conversation. Hovering over an editable model or STL reveals nearby triangle edges with the same Gaussian fade. Where regions overlap, the agent’s teal confirmation takes precedence. The invisible hover region follows the nearest visible surface, uses a nominal 60 CSS-pixel radius, and updates at most once per display frame without a painted trail or session writes. Leaving the canvas, losing window focus, or replacing the model clears it; camera gestures remain available. Hover is omitted from project covers. Source revisions and model replacement clear the highlight; stale identities and source errors reject new highlights without replacing the previous state. An empty blob list clears the reference. Tool requests and returned regions are recorded by the normal tool conversation events; presentation state itself is session-memory only. `viewer_highlight` waits up to eight seconds for the visible renderer to acknowledge the matching highlight ID and source identity. Only `rendered` confirms rendering; `not_rendered`, cancellation, or replacement cannot be described as a visible highlight. Rendering is not user confirmation; this tool does not capture screenshots. The skill requires visual grounding for region-specific edits and named parts. Clear requests and offered choices are handled in context; ambiguous intent needs clarification. There is no confirmation-phrase parser or highlight-based edit gate.

Cursor modes sit in a compact glass pill at the bottom left. With a mouse or trackpad, only the active mode is visible until hover or keyboard focus reveals all four choices; focus keeps the choices open while selecting. Touch controls remain expanded with 44px targets. Reduced transparency and increased contrast use an opaque background.

`viewer_cursor_snapshot` requests a fresh capture from the open viewer in the calling conversation. It samples the active cursor when the viewer processes the request, through a session-scoped long-poll wakeup; it never returns an earlier hover. A successful result includes a PNG attachment, capture time, pointed object or part path, triangle index, world-space point and Gaussian radius, camera, and geometry/placement identity. Editable-model hits include `region.modelLocalBlob` in the coordinates accepted by `viewer_highlight`; use the accompanying `identity.design` to propose the same region independently. Hover is not a persistent selection or an exact triangle mask.

Only requested captures cross to the host. Live Voice requests one at the first transcript chunk since its preceding delegation and records the timestamped result and image in separate background context linked to the spoken message ID. The user’s voice bubble contains only their words. This approximates pointing during speech; it is not audio-onset sampling. The agent must use that attached reference for the utterance rather than substitute a later cursor position. Viewer wakeups also deliver highlight changes without waiting for the two-second scene poll. The tool's structured result and durable image attachment enter the normal conversation log, making the agent's visual input replayable. Missing intersections report `no_hit`; closed or nonresponding viewers report `viewer_unavailable` after at most eight seconds. Changed source/placement identities report `stale_view`, capture or image-storage failures report `capture_failed`, and a concurrent request reports `busy`. Cancellation, scene eviction, and plugin disposal release pending requests. Responses are session/request scoped and validated before entering tool output. Images are limited to a 960-pixel longest edge and three million encoded characters; the attachment service validates and stores their PNG bytes. Agent highlights remain independently controlled by `viewer_highlight` and do not move with the cursor.

### Highlight diagnostics

`viewerDiagnosticsDirectory` defaults to `~/.rumi/viewer-logs`. Private JSONL files record highlight request IDs, host wakeups and state delivery, client apply and feedback phases, document visibility, viewport dimensions, identity comparisons, and settlement latency. Client durations use a monotonic clock; host receipt times establish cross-process order. No model source, images, audio, transcript text, or credentials are recorded. Files remain until deleted. Journal I/O errors fail the owning operation; failed client trace delivery also reports to the browser console.

`not_rendered` includes `reason`: `ack_timeout` means no matching acknowledgment arrived and does not establish that the highlight was absent; `viewer_hidden` and `render_failed` are explicit renderer reports. Returning a hidden document to view redraws and reports the current highlight. A highlight-only update reuses the geometry, materials, and measurement report; only region uniforms change. Placement, volume, and source changes invalidate measurements. The CPU diagnostic `node --import tsx/esm apps/rumi/brand/print-studio/tests/viewer-highlight.perf.ts` compares uniform updates with `--rebuild`; it excludes network, model response, and GPU time.

### Cursor driven mesh highlighting

The cursor clips its Gaussian patch to the pointed mesh and a connected surface. Surfaces stop at open edges, material seams and creases of at least 35 degrees; they are geometric regions, not semantic anatomy. The local controls select a patch, full surface, whole mesh part, or nearby boundary edge. They share the model selector’s rounded glass material, with an inset selected segment and visible keyboard focus. The viewer builds a geometry-local octree and surface attributes once per display copy; pointer movement updates uniforms at most once per frame without model calls, host requests, geometry uploads, or flood fills. Index preparation happens when a model loads; it is not included in steady-state picking latency.

Snapshots include `region.selection` and a bounded, viewport-local `anchorId`. Passing selection with the blob to `viewer_highlight` reproduces the scope in teal on the exact source revision. Live Voice recognizes only complete short selection requests (“local patch”, “whole panel”, “whole part”, “just the edge”, “larger selection”, “smaller selection”, and Chinese equivalents). Transcript chunks refine the initial captured anchor directly through the viewer; arbitrary editing language still goes to the agent. Refinements and their images replace the separate logged reference, leaving spoken text untouched. Recognition and transport latency remain separate from local cursor latency. Model or placement changes invalidate anchors; bilateral interpretation remains agent-owned because the viewer does not infer a symmetry axis.

## Analog mesh editing

The agent opens `viewer_controls` with declarations for labeled sliders, two-axis pads, and scalar curves. Each axis binds a numeric value and declares its range, step, and reset value. A panel may expose only some of the supplied model parameters. The renderer is independent of the model operation; labels describe actual bindings. Controls float at the viewer’s top right, scroll when needed, and support keyboard input, per-control reset, focus indicators, and reduced transparency. The [interactive-controls skill](skills/interactive-controls/SKILL.md) teaches when to offer controls and gives bulge and cut examples. Its active workflow prompt also applies to existing projects.

Executable JavaScript parameter previews are disabled. Geometry adapters retain their geometry behavior: bulge, bend, twist, and taper update GPU uniforms without rebuilding. Their declared axes use normalized 0..1 values and neutral .5. Read [analog-shaping](skills/analog-shaping/SKILL.md) for their region and save contracts. Local edits temporarily suspend cursor selection and thumbnails; geometry checks describe the saved original.

Releasing a control updates session-owned values. Satisfaction or a new task resolves the latest visible edit first; explicit cancellation discards it. Freeze captures fresh visible values, locks controls, and writes a source-bound recipe under `artifacts/shape-controls/`. The agent applies the recipe to the matching Blender source with `apply_shape_controls`, publishes a new revision, and loads it. Close restores the saved preview. Source changes invalidate controls; stale feedback is rejected. Hidden viewers report `viewer_hidden` and render the same controls when visible again. Rendering exceptions report `render_failed` with the cause in control state and the tool result. Neither preview nor save certifies print readiness.

`viewer_controls` replaces `viewer_shape_controls`; callers must supply explicit control declarations when opening. Stored legacy recipes retain their geometry format. An arbitrary Blender parameter needs a faithful live binding before it can have controls; renaming a deformation slider does not create that binding.

Continuous planar cuts use Height, Tilt and Lean controls on the same floating glass surfaces. Opening cut controls clears prior Gaussian highlights; a continuous teal guide follows the actual cut edge instead of scattered blobs. The guide disappears on freeze or close, and new region highlights are rejected until the cut is resolved. The preview clips selected parts against one model-local plane and draws stencil cross-sections without rebuilding geometry; cavity openings remain visible. The saved recipe uses Blender’s exact Boolean intersection to trim and cap the same retained half-space. Height travels by ±limit along direction; Tilt and Lean span ±60° around the neutral plane. A request to edit a cut opens these controls before applying it. To restore already removed material, start from an earlier revision. Curved cuts, extrusion and bevel still require ordinary Blender editing. The Blender regression runs with `blender --background --python-exit-code 1 --python tests/blender-cut.py -- blender/rumi_blender.py` from this package directory.

## Live model context

Print Studio maintains viewer state as selection, source, measurements, highlights, and shape controls change. Its required `rumi:mesh-state` context provider synchronously reads that state before each model attempt, including retries; it performs no file discovery or viewer operation. The snapshot includes the complete scene report and working models. Before the viewer initializes, it reports `viewer_not_initialized` rather than claiming an empty scene. Model discovery and source polling remain viewer-owned. State changes alone do not wake the agent.

Rumi retires previous runtime-context snapshots through native durable surface replacements during `agent/request`; empty developer replacements contribute no model-visible message, and the ordinary agent loop admits the fresh snapshot. Original snapshots remain in the session log, while human messages, action results, and request-time references remain intact. This refresh also replaces unchanged snapshots and can reduce provider prefix-cache reuse; it guarantees one current snapshot across route preparation and retries without modifying shared harness code. The `mesh_state` tool is not registered. Tools validate revision identity when acting because viewer state can change during model generation.

## Model selection and agent work

The selected model is the user's browsing state. A small green dot on a model selector button identifies the agent's declared work independently of selection; its accessible name explains the dot. The `viewer_working_model` tool validates a discovered model entry, sets or clears the declaration, and never switches the preview. Concurrent agents may identify different models. Idle, cancellation settling to idle, agent disposal, and plugin disposal clear their indicators. Selected-model placement, highlighting, and shaping reject a selection that conflicts with the declared work target. A declaration reports intent; it does not verify which files a shell command edits.

The required `rumi:model-focus` runtime context uses `ctx.systemPrompt.context` and is recorded by the agent loop. It includes current selection, available models, the agent's work target, and message-ID-linked selections captured when human requests enter the inbox. Queued requests retain their individual references even if the user browses elsewhere. References unavailable after restart remain unknown rather than borrowing the current selection. Voice additionally records selection at the initial transcript capture alongside its pointing reference. Names and pointing references take precedence; selection supplies a default, browsing alone never retargets ongoing work, and conflicting intent requires clarification. Clear the work declaration before asking that clarification. New models acquire an indicator after their entry exists and the agent declares it.

Opening a project restores validation history without running checks. Publishing prints cheap findings; the agent starts Bullet and acceptance through the validation tools. Validation findings do not hide models.

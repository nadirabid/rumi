# Print Studio

[English](README.md) | 中文

为 Rumi 的 3D 打印工作流提供环境检测和 Bambu Lab 配置引导。

此功能涵盖环境配置和实际测试打印，回答三个配置问题，并提供一条端到端打印路径：

- 是否已安装 Bambu Studio？
- 是否包含 H2D 配置文件？
- 是否已配置打印机，并且可通过局域网访问？

主机端通过 SSDP 发现打印机，提供 `GET /api/print-studio/status`、`/api/print-studio/cloud/*` 下的 Bambu Cloud 路由、`/api/print-studio/viewer/*` 下的网格预览路由，以及面向模型的工具。登录会获取已绑定打印机的 `dev_access_code`；Bambu Connect 负责发送切片后的任务。浏览器端包括**插件 → 内置插件设置**中的 Print Studio 卡片和 3D 预览标签页。内置的[配置技能](skills/print-studio-setup/SKILL.md)和 [FDM 设计技能](skills/fdm-design/SKILL.md)在插件加载时注册，供智能体发现。它们提供配置引导和设计约束；智能体在需要时加载相应说明。

打印机 IP 和序列号存储在 `$DSH_HOME/print-studio/printer.json` 中，仅所有者可访问。局域网访问码通过 `ctx.credentials` 存储为 `BAMBU_LAN_ACCESS_CODE`；它不会返回给客户端，也不会写入配置补丁。

[打印机感知技能](skills/printer-awareness/SKILL.md)将实时状态工具和已安装的机器配置用于打印机相关决策，保留未知读数，并要求打印空间具有明确来源。

## 测试打印

`POST /api/print-studio/print/test`（以及 `print_studio_print_test` 工具）使用 Bambu Studio 对内置的 10 x 10 x 1.2 mm 测试块进行切片，设置 H2D 双挤出机项目和 Supertack 打印板，并将切片后的 3MF 交给 Bambu Connect。Bambu Connect 要求成年人点击**发送**；macOS 上没有支持这一步最终授权的 API。`GET /api/print-studio/print/status` 和 `print_studio_progress` 通过本地 MQTT 读取进度、层数、温度、AMS 和错误。

测试块的打印时间约为六分钟。

## 网格预览

模型预览通过 Three.js 的统一 USD 加载路径显示。导入的 STL 三角形转换为 USD；Blender 发布 `model.usda`，可编辑 `.blend` 原件单独保留。USD Physics 关节及 Isaac 机器人注解描述显示与验证所用的同一组网格。运动控件变换已加载装配，不重建几何。

`viewer/` 模块为任意对话提供通用 3D 视口；打印只是它的调用方之一，并非其唯一用途。一个目录对应一个 Cordis 插件，因此它随此插件发布，不单独成为一个包。

STL 场景文档将几何数据与放置方式分开：

- **数据块**表示一个网格：主机读取的几何数据、规范化的 STL 字节，以及
  旋转时所围绕的中心；
- **对象**通过缩放、旋转和位置放置一个数据块；缩放和
  旋转围绕网格中心进行，位置表示底部中心的所在位置，
  因此部件放大或转动后仍位于打印板上
- **场景**包含对象，以及用于检查它们的打印空间。

同一文件打开两次会放置两个共享同一数据块的对象，因此浏览器只获取一次几何数据，每次放置变更都无需改动它。

每次变更都是一条命令（`addObject`、`removeObject`、`setTransform`、`setVisible`、`setVolume`），命令返回一个新文档，因此撤销记录是一组先前的文档。智能体通过 `mesh_open`、`mesh_transform` 和 `mesh_remove` 发出命令，并通过 `meshState` 读取结果；将来的操纵控件也会使用相同命令。

`GET /api/print-studio/viewer/state?sessionId=…` 返回浏览器绘制的场景，包括每个对象的放置矩阵、状态和计数。`GET /api/print-studio/viewer/model?sessionId=…&datablockId=…` 返回一个数据块的字节；这些字节打开后不会变化，并按不可变内容缓存。

`bake.js` 将场景转换为文件数据：每个可见对象生成一个已应用变换的网格。它使用与测量相同的放置计算。导出和切片可以使用这些网格，无需修改源文件。

STL 导入接受最大 20 MiB、200,000 个三角形的文件。可编辑设计使用 [Three.js 模型接口](#editable-threejs-models)。场景和数据块为八个对话保留在内存中，在插件卸载时消失。从对话中打开的 STL 使用相同的标签页类型进行文件预览。

只有 `viewport/` 导入 Three.js。两种模型都使用 `transform.js` 处理放置；`bake.js` 为导出准备已放置的 STL 几何数据。

## 客户端构建

这是携带渲染器的 Cordis 配置项，因此浏览器端经过打包，而不是以普通 JavaScript 提供：Three.js 仅供此配置项使用，不进入共享的客户端模块表。`esbuild` 和 `three` 是 `apps/rumi` 的开发依赖；`build-client.mjs` 生成 `lib/client.js`，并在旁边放置 Three 的许可证。

```sh
pnpm --filter dsh-rumi run build:print-studio-client   # or `run build`, which includes it
```

## 账户登录

设置卡片在独立的 Rumi 桌面窗口中打开 Bambu 托管的登录页。桌面适配器只接受该窗口中位于 `https://bambulab.com` 的主框架发送的登录消息。社交登录打开系统浏览器，并通过临时回环监听器返回。关闭窗口、关闭 Rumi 或达到三分钟期限时，会移除监听器和消息处理器。

窗口在用户代理中提供以空格分隔的 `BBL-Slicer/v02.08.02.61` 标记，使 Bambu 页面启用 Studio 票据回调。页面通过 `get_localhost_url` 获得 `http://localhost:<port>` 地址后才打开系统浏览器；Bambu 拒绝数字形式的回环地址。浏览器登录必须保留该返回地址。收到票据后关闭登录窗口，并将焦点移回 Rumi。

Print Studio 验证返回消息，通过 Bambu 的票据端点交换票据，并通过 `ctx.credentials` 存储凭据。桌面适配器不保留令牌或密码。浏览器卡片需要 Rumi 的桌面桥接；独立的 DSH Web 无法打开此原生登录窗口。

托管页面和票据交换已使用真实 Bambu 账户验证；Bambu 更改页面后应重新验证。本地测试覆盖用户代理格式、回调地址、票据传递、窗口清理、消息验证和票据请求。

## Blender 编辑和 USD 预览

新建模型和网格编辑通过现有 shell 工具及其权限运行本地 Blender 后台 Python 脚本。打包后的 Rumi 在 `Resources/runtime/blender` 中包含 Blender；应用更新会将该运行时替换为固定版本。`blender_status` 默认使用内置运行时，安装损坏时报告错误，不会静默回退到独立安装。显式配置的 `blenderExecutable` 优先于自动发现。开发检出可使用 `blenderHome/tools/blender/Blender.app`、`/Applications/Blender.app` 或用户的 Applications 文件夹；`blenderHome` 默认为 `DSH_RUMI_HOME` 或 `~/.rumi`。随附的 [blender-modeling 技能](skills/blender-modeling/SKILL.md) 定义代理工作流程；状态工具返回已安装导出辅助脚本的路径。

辅助脚本在 `models/<name>/revisions/` 下保存不可变的 `.blend`、USD 和测量版本，再原子替换 `model.usda`。脚本启动完整 Blender 进程而不打开窗口。规范 USD 以米为单位、Z 轴向上；Three.js 转换为毫米、Z 轴向上的光标、测量及高亮坐标。Blender 编辑必须考虑对象变换并将查看器坐标除以 1,000。辅助脚本在原件中保留修改器，在查看导出文件中应用修改器。导出失败保留上一份预览；不完整版本文件保留供诊断。

`viewer_load` 接受项目内的独立 ASCII USD 层，限制为 64 MiB 和 200,000 个可见三角形。在资产解析前拒绝引用、外部资源、组合、变体及动画。网格和内嵌材质值必须保存在一个静态层中。查看器优先发现 `models/<name>/model.usda`，再发现旧入口，并在两次相同轮询后重新加载。不可变快照 URL 保留光标及高亮的版本身份。无效导出保留上次成功预览并报告错误。这些检查不证明可打印性。

`viewer_load` 选择模型并唤醒查看器并等待与显示的 URL、修订、变换和构建体积匹配的反馈。`load.status: ready` 确认可见渲染；`design.report` 包含测量结果，`design.parameters` 包含声明的默认值和已保存的值。构建和源文件失败返回对应错误；查看器隐藏、超时、替换、取消和卸载分别返回不同的未就绪结果。超时不代表模型不受支持。确认失败时选择仍然生效；不得据此推断已回滚或可打印。在 Print Studio 配置行设置 `viewerLoadTimeoutMs`（默认 8000 毫秒，范围 1–25000 毫秒）。

建模技能在编辑前提供[实体构建默认规则](skills/blender-modeling/SKILL.md#solid-construction-defaults)：封闭实体、Exact 布尔运算、独立机械部件、受控细节处理和选择性重网格化。这些是智能体指令，不是强制执行的操作限制；几何验证仍会检查结果。

## 自动 Blender 验证

Print Studio 监听 DSH 的 `turn/end` 事件并扫描所有已发现模型，不依赖查看器选择或代理工具调用。源文件字节、JavaScript 辅助模块、已保存参数、放置变换、打印体积和验证设置共同标识已检查的修订。未变化的已完成结果会复用。新回合开始时取消尚未完成的工作；在回合结束扫描确认当前修订前，旧结果明确作为历史记录保留。检查结果记录在 `meshState.validation` 中；未解决的错误、不可用的检查或需要复核的机械检查结果在查看器右下角显示为小红点。失败或几何不可用绝不视为通过。

成功完成一轮后，阻断性结果或未验证的机械检查会自动排入一个 `print-validation` 智能体后续轮次，其中包含模型路径、版本指纹和报告。所有待处理的模型检查结束后才发送请求。智能体保留所需设计并修复已保存的几何与装配声明；仅有静态警告或检查不可用时不会触发几何修复。每项用户任务对每个版本只请求一次，最多执行 `validationRepairAttempts` 轮修复（默认 5，设为 0 则禁用）。新的用户消息重置此预算。中止或失败的轮次不会触发修复。查看器右下角的小红点表示未解决的错误或检查不可用；修复期间及预算耗尽后仍保留，只有新的通过结果才清除。这是自动修复辅助，不保证可打印性。

USD 快照通过后台 Blender 检查，在转换为毫米前应用完整父级变换。旧模型必须导出 USD 后才能验证。源文件变化会丢弃过期结果；关闭时先终止并等待子进程，再释放临时文件和路由。验证及修复期间显示当前模型。接受要求无阻断性几何结果且机械报告通过并覆盖完整，但不限制预览可见性。静态警告保留在报告中。`validationStateDirectory` 默认为 Rumi 主目录下的 `validation`，原子保存已接受原件及必需运动意图；状态不可用或损坏会阻止接受。不改写现有项目文件。重启后仍可恢复已接受快照，并在下一轮完成后检查当前模型。

固定版本的 GPL 许可 3D Print Toolbox 源码及许可证随包保存在 `blender/object_print3d_utils/`；`UPSTREAM.json` 标识源码修订。适配器检查流形、绕序、相交、退化、扭曲、厚度、锐边和悬垂。几何以毫米计，位置焊接容差为 0.001 mm。配置项为 `validation.minimumThicknessMm`（默认 1）、`degenerateThreshold`（0.000001，Toolbox 同时用于边长和面面积）、`overhangDegrees`（45）、`sharpDegrees`（160）及 `distortionDegrees`（45）。`validationTimeoutMs` 默认为 60000。这些是筛查阈值，并非经校准的打印公差。厚度采样和悬垂结果需要复核；有意重叠的实体也需要判断。对于包含两个或更多部件的装配，当两个不同部件之间的表面间隙小于 `validation.minimumClearanceMm`（默认 0.2，范围 0–2，0 表示禁用）时，两种制造模式下 `insufficient_clearance` 均为错误。间隙按放置后的毫米坐标测量，覆盖除由 `fixed` 连接直接相连的部件对之外的所有部件对；重叠报告为 0，`details.pairs` 按间隙从小到大列出最多八对及其 `gapMm`。该度量为顶点到表面的距离，可能漏掉纯边到边的最小值；通过不代表装配间隙可打印。已声明的运动接受下述额外检查。不会认证装配、支撑、材料强度或最终切片就绪性。查看器仅保留输入和预览限制，以及尺寸和包络测量。

在本包目录运行 `Blender --background --factory-startup --python-exit-code 1 --python tests/blender-validation.py` 可执行真实 Toolbox 回归。会话测试覆盖回合结束触发、未变化修订、渲染进程交接、过期结果和失败。

## 机械验证

模型使用 USD Physics 刚体、碰撞 API 以及固定、旋转或滑动关节。默认 prim 应用 `IsaacRobotAPI`；有序的 `isaac:physics:robotLinks` 和 `isaac:physics:robotJoints` 关系列出每个网格与关节。链接应用 `IsaacLinkAPI`，关节应用 `IsaacJointAPI`，首个链接是固定测试根部件。标准刚体关系、局部坐标系与限位定义预期运动；每个链接必须连接到根部件。旋转限位用度，滑动限位用米。关节两侧坐标系必须在保存的静止姿态相交，运动轴必须一致。有限范围定义覆盖要求，不代表存在物理限位。`rumi:control`、`rumi:manufacturingMode`、`rumi:sequences` 和 `rumi:disassembly` 保存 Rumi 特有的控件及制造要求。运动意图跨版本和重启保留；删除必需控件或缩小范围不能掩盖失败检查。参见[物理运动声明](skills/blender-modeling/SKILL.md#declare-physical-movement)。

Blender 未发现阻断性几何错误后，主机通过协议 2 将求值后的物理网格及装配描述传给内置 Bullet 程序。双精度 GImpact 接触保留凹几何。仅固定声明的根部件；包括保持件在内的所有其他部件均保持动态。固定、旋转和滑动连接仅描述预期相对行为，不创建理想关节。通用探测挑战禁止运动，并通过力驱动允许运动到采样姿态，同时监测每个连接及碰撞对。保持检查测试的是脱离而非紧度：部件可在其间隙内移动，只要连接几何将其限制在 `mechanics.retentionTravelMm`（默认 2，范围 0.1–10）的枢轴位移和 `mechanics.retentionTiltDegrees`（默认 15，范围 1–45）的倾斜之内即通过。部件位移或倾斜超出任一界限，或保持探测结束时仍在向外移动，则报告 `unstable_at_rest` 和 `unretained_part`。`linearToleranceMm` 和 `angularToleranceDegrees` 仅决定被驱动关节是否到达目标（`movement_blocked`）以及 `movement_below_tolerance`。报告记录部件、连接和序列覆盖，以及解析后的仿真策略。错误加入现有修复请求；不支持的物理行为及不完整覆盖保持未验证状态。程序缺失、超时或报告格式错误均不能通过。`mechanics.maxTotalSteps` 默认为 2,000,000（可配置为 1,000 至 10,000,000），超出后装配保持未验证；即使跳过完整运动，初始连接检查仍会报告缺陷。

装配最多包含 128 个物理部件和 128 个连接。将不连通实体合并为一个网格不能提供物理连接。`publish(directory, configure_robot=callback)` 向回调提供 OpenUSD stage 以编写标准声明，并在可编辑 `.blend` 中保留其 USD 层；省略回调保留已有声明。Blender 内置 OpenUSD 按照 NVIDIA 的[无 Kit 方案](https://nvidia.github.io/simready-foundation/2026.07.1/features/FET_101_ISAAC.html)直接编写 Isaac 注解，无需 Isaac Sim。注解描述预期行为，Bullet 探测网格是否实现该行为。不支持的图耦合、变形连接及数值不确定性需要复核。未声明 `rumi:disassembly` 步骤的 `separate` 装配仅由探测验证；仅当声明这些步骤（仅平移的逆向装配路径）时才检查移除路径。

`bulletExecutable` 指定开发环境的显式路径；打包后的 Rumi 使用内置程序，不搜索 `PATH`。`mechanicsTimeoutMs` 默认为 600000（十分钟），独立限制实际运行时间。`mechanics.retentionWorkers` 默认为 4（可配置为 1–4）：初始检查通过后，独立保持载荷以有界批次并行运行，各工作线程使用独立碰撞形状。运动步骤仍按顺序执行；结果保持串行顺序，且始终监测每个连接。每个连接的独立保持载荷在保存姿态和每个范围端点姿态运行；中间运动采样和返回运动仅探测被移动的连接。对于序列，最后一个路点探测每个连接，中间路点仅探测被驱动的连接。不会根据表面对称性或距离省略探测。原生报告上限为 8 MiB。智能体上下文和修复请求汇总通过的探测数量，并保留所有失败或不确定的探测、覆盖范围及策略；查看器状态保留完整诊断报告。`mechanics` 策略配置密度、力及扭矩上限、持续时间、积分、接触容差、重力、摩擦和采样。默认重力为 `[0,0,-9.81]` m/s²，摩擦系数为 `0.2`，运动采样间隔为 30 度或 2 mm，`probeDurationSeconds` 为 0.25，`maxPenetrationMm` 为 0.15，拆卸路径采样间隔为 0.2 mm。这些是筛查假设，并非经过校准的打印机或材料参数。通过仅涵盖报告中的有限探测，不能保证连续无碰撞、所有同时运动组合、支撑移除、强度、磨损、变形或切片就绪。`printReady` 保持为 false。

## 持久活动部件控件

运动控件位于查看器右下角，与光标控件相对，独立于临时编辑控件。控件使用内高光，不带外部阴影。运动只改变本地预览姿态，不修改验证输入。临时编辑期间面板保持可见但被禁用。请求绑定源码的光标编辑前请重置姿态；预览运动不代表机械验证通过。

USD 旋转及滑动关节生成滑块，提供 `rumi:control` 时用其作为标签，否则使用子部件网格名称。预览按关节坐标系变换部件及其后代，包括固定附件。共享控件使用范围交集且单位必须一致。最多支持 12 个独立控件；声明无效、闭环或不支持的绑定保留可见几何并报告 `assembly_motion_unavailable`，不显示误导性控件。装配声明不变时姿态值跨重新加载保留。预览借用原始网格资源，不修改导出几何，也不代表机械验证通过。

## 可编辑的 Three.js 模型

将每个独立预览保存在 `models/<name>/model.usda`，并保留可编辑 Blender 原件。查看器通过 Three.js 渲染 USD，不执行项目代码。迁移 GLB 模型时，打开其 `.blend` 或使用辅助脚本 `import_mesh` 导入 GLB，再调用 `publish`。旧装配声明一次性转换为 USD Physics 关节，此后保留原生 USD 描述。保留原文件。旧 JavaScript 入口必须通过受限建模工具导出真实几何。不会自动迁移任何项目。

`viewer_transform` 在不修改源码的情况下应用统一缩放、以度为单位的 XYZ 旋转，以及以毫米为单位的底部中心位置。`viewer_camera` 根据方位角和仰角调整观看方向，不改变几何数据。两者均作用于整个已加载设计；命名部件通过源码编辑。成功重建后保留相机状态和放置方式。导入或构建失败时保留上次成功的模型，并显示错误；`meshState` 包含源码版本、构建错误和渲染进程报告的测量结果。测量需要预览处于挂载状态，且不能证明模型已可打印。现有的 STL 导入和场景工具仍可单独使用。

每个对话拥有独立的实时预览。最后选择的入口和打印平台尺寸以原子方式保存在项目的 `.rumi-viewer.json` 中，重启后打开预览时恢复；没有保存的选择时打开第一个发现的模型。切换模型会在主机接受选择后立即刷新预览，无需等待定期轮询，并重置相机和位置。保存的入口缺失或不可读时显示错误，不会替换为其他模型；选择可用模型即可恢复。自动发现排除符号链接目录和入口。仅加载选中的源文件，其他模型文件保留在磁盘上。STL 场景对象仍仅保存在内存中。

源码加载和快照是由 Print Studio 插件拥有的 Cordis effects。快照 effect 收集路由注册返回的原始 disposer。卸载会停止源码轮询，等待已接纳的加载和轮询结束，并释放路由；查看器丢弃延迟完成的导入，并释放 GPU 资源。测试使用真实 Cordis 上下文验证这些路径。

### 视觉澄清

内置的 `clarify-mesh-changes` 技能指导区域识别及修改意图澄清。`viewer_highlight` 可替换通过 `viewer_load` 加载的可编辑模型上的最多八个高斯椭球；不支持 STL 导入。传入 `meshState` 中的 `design.path`、`design.revision`、`design.url`，简短的 `label`，以及包含三个数字的 `center`、`radii`、`rotationDegrees` 数组的 `blobs`。坐标为模型局部毫米坐标，包含部件变换，但不包含整体放置；旋转使用 XYZ 欧拉角（度）。半径表示名义范围：逆旋转并除以半径后，影响强度为 `exp(-1.5 * dot(q,q))`，多个区域取最大值，再通过 `smoothstep(0.08,0.42,influence)` 渐变。所有相交表面都可能受影响，包括薄壳背面。

agent 区域使用青绿色填充和深色线框，指针区域使用蓝色填充和深蓝色边缘，在色调映射前与着色表面混合，不受应用主题影响。视口在柔和区域内显示三角形边缘，不修改源几何、材质、测量、导出或项目封面。agent 提出的高亮通过对话控制。将指针悬停在可编辑模型或 STL 上，会以相同的高斯渐变显示附近的三角形边缘。区域重叠时，agent 的青色确认优先。不可见的悬停区域跟随最近的可见表面，名义半径为 60 CSS 像素，每个显示帧最多更新一次，不留下绘制轨迹，也不写入 Session。指针离开画布、窗口失去焦点或替换模型时会清除该区域；相机手势仍然可用。项目封面不包含悬停效果。源码版本变化或模型替换会清除高亮；过期标识和源码错误会拒绝新的高亮而不替换先前状态。空区域列表清除引用。工具请求和返回区域通过常规工具对话事件记录；显示状态本身只保留在会话内存中。只有工具结果 `rendered` 才确认可见查看器已渲染该高亮，但仍不表示用户已确认；此工具不截图。技能要求使用高亮为局部编辑和部位名称提供视觉依据；明确请求直接按上下文处理，仅在意图不清楚时澄清。

光标模式位于左下角的紧凑玻璃胶囊中。使用鼠标或触控板时，仅显示当前模式；悬停或键盘聚焦后显示全部四个选项，选择期间焦点会保持展开。触屏控件始终展开，点击区域为 44px。减少透明度或提高对比度时使用不透明背景。

`viewer_cursor_snapshot` 从调用方对话中打开的查看器请求一次新的捕获。它在查看器处理请求时采样当前指针，通过按 Session 隔离的长轮询立即唤醒；绝不返回之前的悬停位置。成功结果包含 PNG 附件、捕获时间、指向的对象或部件路径、三角形索引、世界坐标中的位置和高斯半径、相机，以及几何和放置标识。命中可编辑模型时，还会返回使用 `viewer_highlight` 坐标系的 `region.modelLocalBlob`；结合 `identity.design`，可独立提出同一区域。悬停既不是持久选择，也不是精确的三角形蒙版。

只有请求的捕获会传输到主机。工具的结构化结果和持久图像附件进入常规对话日志，使 agent 的视觉输入可回放。没有交点时返回 `no_hit`；查看器关闭或未响应时，在最多八秒后返回 `viewer_unavailable`。源码或放置标识变化时返回 `stale_view`，捕获或图像存储失败时返回 `capture_failed`，并发请求返回 `busy`。取消、场景淘汰和插件卸载都会释放待处理请求。响应按 Session 和请求隔离，并在进入工具输出前验证。图像最长边限制为 960 像素，编码字符数不超过三百万；附件服务验证并存储 PNG 字节。agent 高亮仍由 `viewer_highlight` 独立控制，不随指针移动。

没有固定确认短语解析器或基于高亮的编辑门禁。明确请求和已提供的选项按上下文处理；意图不明确时需要澄清。Live Voice 在上次委派后的第一个转录片段到达时请求捕获，并将带时间戳的结果和图像保存为与用户语音消息 ID 关联的独立后台上下文。用户语音气泡只显示其话语。这近似于说话时的指向，不是音频起点采样。agent 必须使用附带引用，不能用后来的指针位置替代。查看器唤醒也会立即传递高亮更新，无需等待两秒场景轮询。

`viewer_highlight` 最多等待八秒，直到可见渲染器确认匹配的高亮 ID 和源码标识。只有 `rendered` 表示已渲染；`not_rendered`、取消或被替换都不能描述为高亮已显示。渲染不等于用户确认，此工具不捕获截图。

### 高亮诊断

`viewerDiagnosticsDirectory` 默认为 `~/.rumi/viewer-logs`。私有 JSONL 文件记录高亮请求 ID、主机唤醒与状态传递、客户端应用与反馈阶段、文档可见性、视口尺寸、标识比较以及完成耗时。客户端耗时使用单调时钟；主机接收时间用于确定跨进程顺序。不记录模型源码、图像、音频、转录文本或凭据。文件保留到手动删除。日志 I/O 错误会使所属操作失败；客户端诊断传递失败也会报告到浏览器控制台。

`not_rendered` 包含 `reason`：`ack_timeout` 表示没有收到匹配确认，并不能证明高亮未显示；`viewer_hidden` 和 `render_failed` 是渲染器明确报告的状态。隐藏文档恢复可见时会重绘并报告当前高亮。仅高亮更新会复用几何、材质和测量报告，只更改区域 uniform。放置、构建体积和源码变化会使测量失效。CPU 诊断命令 `node --import tsx/esm apps/rumi/brand/print-studio/tests/viewer-highlight.perf.ts` 可通过 `--rebuild` 比较 uniform 更新与重建；它不包含网络、模型响应或 GPU 耗时。

### 光标驱动的网格高亮

光标将高斯局部选区限制在所指网格及其连通表面内。表面在开放边缘、材质接缝和至少 35 度的折角处终止；这些是几何区域，不是语义解剖部位。本地控件可选择局部、完整表面、整个网格部件或附近的边界边缘。控件与模型选择器共用圆角玻璃质感，选中项显示为内嵌分段，并提供清晰的键盘焦点。查看器为每个显示副本一次性构建几何局部八叉树和表面属性；指针移动每帧最多更新一次 uniform，无需模型调用、主机请求、几何上传或洪水填充。索引在模型加载时准备，不计入稳定状态的拾取延迟。

快照包含 `region.selection` 和有界、查看器本地的 `anchorId`。将 selection 与 blob 一起传给 `viewer_highlight`，可在同一源版本上以青色重现选区。Live Voice 仅识别完整的简短选择请求（“local patch”、“whole panel”、“whole part”、“just the edge”、“larger selection”、“smaller selection”及中文对应表达）。转录片段通过查看器直接细化最初捕获的锚点；任意编辑语言仍交给代理。细化结果及图像替换单独记录的引用，语音文本保持原样。识别和传输延迟与本地光标延迟分开计算。模型或位置变化会使锚点失效；双侧解释仍由代理负责，因为查看器不推断对称轴。

## 连续网格编辑

agent 使用 `viewer_controls` 声明带标签的滑块、双轴面板和标量曲线。每个轴绑定一个数值，并指定范围、步长和重置值。面板可以仅展示所提供模型参数中的一部分。渲染器独立于模型操作；标签描述真实绑定。控件悬浮在查看器右上角，必要时可滚动，并支持键盘输入、独立重置、焦点指示和降低透明度。[interactive-controls skill](skills/interactive-controls/SKILL.md) 说明何时提供控件，并给出眼睛倾斜、宽度、位置、鼓起和切割示例。其活动工作流提示词也适用于已有项目。

可执行的 JavaScript 参数预览被禁用。几何适配器保留其几何行为：鼓包、弯曲、扭转和渐缩更新 GPU uniforms，无需重建。声明的轴使用 0..1 归一化值，中性值为 .5。区域与保存规则见 [analog-shaping](skills/analog-shaping/SKILL.md)。本地编辑暂时停用光标选择和缩略图；几何检查描述已保存的原件。

松开控件会更新会话所属的值。用户满意或开始新任务时，先完成最新可见编辑；明确取消则放弃。Freeze 捕获最新可见值、锁定控件，并在 `artifacts/shape-controls/` 写入绑定源文件的配方。代理使用 `apply_shape_controls` 将配方应用于匹配的 Blender 源文件，发布新版本并加载。Close 恢复已保存预览。源文件变化使控件失效；过期反馈被拒绝。隐藏的查看器报告 `viewer_hidden`，恢复可见时渲染相同控件。渲染异常报告 `render_failed`，并在控件状态和工具结果中包含原因。预览和保存都不能认证打印就绪性。

`viewer_controls` 替代 `viewer_shape_controls`；调用者打开控件时必须显式提供控件声明。已存储的旧配方保留几何格式。任意 Blender 参数需要先建立忠实的实时绑定；重命名变形滑块不会创建该绑定。

连续平面切割在相同的悬浮玻璃表面上提供高度、倾斜和侧倾控件。打开切割控件会清除先前的高斯高亮；连续的青色引导线跟随实际切边，替代散布的光斑。冻结或关闭时引导线消失，切割完成前拒绝新的区域高亮。预览以一个模型局部平面裁剪选中的部件，使用模板缓冲区绘制横截面，无需重建几何；空腔开口保持可见。保存的配方使用 Blender 精确布尔交集修剪并封闭相同的保留半空间。高度沿 direction 在 ±limit 范围内移动；倾斜和侧倾相对中性平面各跨越 ±60°。请求编辑切割时会先打开这些控件，再应用结果。要恢复已移除的材料，请从较早的修订开始。曲线切割、挤出和倒角仍需普通 Blender 编辑。在本包目录中运行 `blender --background --python-exit-code 1 --python tests/blender-cut.py -- blender/rumi_blender.py` 可执行 Blender 回归测试。

## 实时模型上下文

Print Studio 根据选择、模型源、测量、高亮和形状控件的变化维护查看器状态。必需的 `rumi:mesh-state` 上下文提供器在每次模型请求（包括重试）前同步读取状态，不扫描文件或操作查看器。快照包含完整场景报告和工作模型。查看器尚未初始化时，返回 `viewer_not_initialized`，而不是声称场景为空。模型发现和源文件轮询仍由查看器负责；状态变化本身不会唤醒智能体。

Rumi 在 `agent/request` 中通过持久化的表面替换移除先前的运行时上下文快照；空的开发者消息替换不会产生模型可见消息，普通智能体循环随后接纳新快照。原始快照保留在会话日志中，用户消息、操作结果和请求时引用保持完整。未变化的快照也会刷新，这可能降低提供器的前缀缓存复用，但无需修改共享框架代码即可保证路由准备和重试期间只有一个当前快照。不注册 `mesh_state` 工具。工具执行时仍验证版本身份，因为模型生成期间查看器状态可能变化。

## 模型选择与智能体工作

选中的模型表示用户的浏览状态。模型选择按钮上的绿色小圆点独立标识智能体声明的工作目标，无障碍名称会说明圆点的含义。`viewer_working_model` 工具验证已发现的模型入口，设置或清除工作目标，但不切换预览。并发智能体可以标识不同模型。进入空闲状态、取消后进入空闲状态、智能体释放和插件释放都会清除对应标识。当所选模型与声明的工作目标冲突时，模型放置、高亮和形状操作会拒绝执行。声明表示工作意图，并不验证 shell 命令实际编辑了哪些文件。

必需的 `rumi:model-focus` 运行时上下文使用 `ctx.systemPrompt.context`，由智能体循环记录。它包含当前选择、可用模型、智能体的工作目标，以及人工请求进入收件箱时捕获的、关联消息 ID 的模型选择。即使用户随后浏览其他模型，排队请求也保留各自的引用。重启后无法恢复的引用保持未知，不以当前选择代替。语音还会在初始转写捕获时记录选择，并与指向引用一起提供。名称和指向引用优先，选择提供默认值；仅浏览不会改变正在进行的工作目标，意图冲突时需要澄清。提出澄清前清除工作声明。新模型在入口存在且智能体声明工作目标后获得标识。

打开空闲项目时会检查现有模型一次，无需等待新的智能体轮次。编辑进行中时，检查延迟到轮次结束。验证结果不会隐藏模型。

# Movement and mesh edit controls

English | [中文](README.zh.md)

Joint controls pose the assembly for inspection. Mesh edit controls preview a temporary visual adjustment on the USD preview that the agent freezes into a recipe JSON and translates into exact `build123d` B-Rep CAD edits. Run the regression commands below from the Print Studio package directory.

## Persistent movement controls

Select a joint pin on the model to open its control. Pins on the camera-facing side of the assembly's estimated center of mass stay visible over the model. Pins behind that center hide when the model blocks them. Orbit the model to reveal a hidden pin. An open control stays visible as you pan, orbit or zoom and moves to the bottom left if its pin leaves view. Select the pin again or press Escape to close it. Pins are hidden during temporary mesh edits. Movement changes only the local preview pose. Cursor highlighting follows the visible parts during movement and after reset. Reset the pose before requesting source-bound cursor edits; preview movement does not establish mechanical acceptance.

USD revolute and prismatic joints generate sliders by default. Optional root `rumi:motionControls` JSON selects sliders, pads, or scalar curves bound to absolute joint paths; undeclared movements retain automatic sliders. Joint limits and the saved pose supply ranges and reset values. See [movement controls](../../skills/cad-modeling/SKILL.md#movement-controls) for authoring. Automatic labels use `rumi:control` or the child mesh name. The preview applies joint frames to each part and its descendants, including fixed attachments. Shared controls use the overlapping declared range and require matching units. Up to 12 independent controls are supported; malformed declarations, closed loops or unsupported bindings keep geometry visible and report `assembly_motion_unavailable` without offering misleading controls. Pose values survive reloads while the assembly description remains identical. Preview transforms borrow original mesh resources and never modify export geometry or imply mechanical acceptance.

## Analog mesh editing

The agent opens `viewer_controls` with declarations for labeled sliders, two-axis pads, and scalar curves. Each axis binds a numeric value and declares its range, step, and reset value. A panel may expose only some of the supplied model parameters. Curve widgets have a centered handle that moves vertically with the value. The renderer is independent of the model operation; labels describe actual bindings. Controls float at the viewer’s top right, scroll when needed, and support keyboard input, per-control reset, focus indicators, and reduced transparency. The [control-widgets skill](../../skills/control-widgets/SKILL.md) describes shared widgets. [Mesh edit controls](../../skills/mesh-edit-controls/SKILL.md) derives useful adjustments from the request, authors their deformations, and handles preview, revision, and saving. Its active workflow prompt also applies to existing projects.

Mesh edit controls use `prepare → validate → review → present`. `open` is an alias for preparation and does not show controls. Preparation snapshots the bindings and requires an expected effect and preserved features for every axis.

Validation uses the saved USD and the viewer’s deformation adapters to render endpoint and combined-extreme comparisons in fixed front, side, and rear views. Images show before, after, and a shared displacement overlay (gray below 0.01 mm, gold through red at 20 mm); cuts show removed regions instead. Measurements come from surface vertices, not lattice peaks. Comparison work yields through the browser task scheduler rather than timers, so hidden-window timer throttling does not delay each case. Auxiliary controls are tested with a nonzero deformation amount. The agent must assess every axis and combined effects before presentation; render completion alone is not approval.

Pending validation or review remains in required context across turns and compaction. A validation timeout retains the prepared id for retry. Reloading identical bytes preserves the source, controls, and review evidence while requesting fresh renderer feedback; stale acknowledgments cannot complete the reload. When no controls remain, context explicitly reports that none are staged or presented. Re-preparing or changing the source invalidates evidence; source disposal or app restart discards pending drafts. Existing visible controls remain intact during preparation. Failed, cancelled, incomplete, or stale validation cannot authorize presentation.

## Freeze and save

Releasing a control updates session-owned values. Satisfaction or a new task resolves the latest visible edit first; explicit cancellation discards it. Freeze captures fresh visible values, locks controls, and writes a source-bound recipe under `artifacts/shape-controls/`. The agent loads the recipe (`load_control_recipe` / `summarize_control_recipe`), applies `cut_solid` for exact B-Rep planar cuts or updates parametric `build123d` dimensions, lofts, or fillets for deformations while preserving exact joints, publishes a new revision, and loads it. Close restores the saved preview. Source changes invalidate controls; stale feedback is rejected. Hidden viewers report `viewer_hidden` and render the same controls when visible again. Rendering exceptions report `render_failed` with the cause in control state and the tool result. Neither preview nor save certifies print readiness.

`viewer_controls` replaces `viewer_shape_controls`; callers must supply explicit control declarations when opening. Stored legacy recipes retain their geometry format. An arbitrary CAD parameter needs a faithful live binding before it can have controls; renaming a deformation slider does not create that binding.

## Deformations and cuts

Executable JavaScript parameter previews are disabled. Geometry adapters retain their geometry behavior: bulge, bend, twist, and taper update GPU uniforms without rebuilding. Their declared axes use normalized 0..1 values and neutral .5. Read [built-in-mesh-operations](../../skills/built-in-mesh-operations/SKILL.md) for their region and save contracts. Hover or click the edited mesh to highlight or pin it in blue, including the retained mesh surfaces during a cut. Adjusting an edit control clears the pin. The viewer pauses cursor snapshots and thumbnails during the edit. Geometry checks describe the saved original.

Model-specific controls use `operation: fields` with data-only displacement lattices. Each control axis needs an entry in `values`, initially zero for fields. Validation distinguishes missing or malformed `values`, missing or duplicate bindings, invalid numbers, and more than 32 parameters; errors name the correction. The viewer interpolates and blends these fields on copies of selected USD mesh geometry; cancel restores the original. Frozen recipes capture the chosen values so the agent can update parametric `build123d` dimensions and profiles cleanly. No project code executes in the viewer. These edits preserve connectivity but do not guarantee thickness or freedom from intersections. See [field authoring](../../skills/mesh-edit-controls/references/fields.md).

The `surface` operation uses model-space selection bounds, so triangle expansion does not change its frame. Profile stations move along a continuous side-view outline, including vertical crown motion, with a smooth lateral fade and a pinned underside seam. Stations can be pinned or share a displacement control and direction to preserve a rigid section. Rings and channels use radial movement; channel width is arc length. Facets project onto declared planes within a height-band core and blend at its edges. Oriented hollow shells can declare wall thickness to target separate outer and inner planes; ambiguous rim edges fail before preview. Surface evidence rejects collapsed or inverted triangles.

Before image review, the host checks the actual preview triangles with `cad/control_geometry.py` (pure Python/NumPy spatial-hash Möller–Trumbore intersection) and blocks new intersecting pairs at each endpoint and combined extreme, including intersections with unedited parts. Existing pairs remain reported; a nearby source defect cannot excuse a new pair. Thickness and mating fit still require measurement; identical displacement does not guarantee preservation. Source hashes bind frozen recipes to the reviewed model.

Continuous planar cuts use Height, Tilt and Lean controls on the same floating glass surfaces. Opening cut controls clears prior mesh highlights; a continuous teal guide follows the actual cut edge instead of scattered blobs. The guide disappears on freeze or close, and new region highlights are rejected until the cut is resolved. The preview clips selected parts against one model-local plane and draws stencil cross-sections without rebuilding geometry; cavity openings remain visible.

The saved cut uses `helper["cut_solid"](part, recipe)` in `build123d` to trim and cap the same retained half-space in exact B-Rep. Height travels by ±limit along direction; Tilt and Lean span ±60° around the neutral plane. A request to edit a cut opens these controls before applying it. To restore already removed material, start from an earlier revision. Curved cuts, extrusion and bevel still use parametric `build123d` modeling.

## Surface regression checks

`tests/surface.spec.ts` covers crown continuity, rotated frames, planar patches, shell offsets, and rejection. `tests/cad-control-geometry.py` verifies `cad/control_geometry.py` triangle-triangle intersection checks against the bundled CAD Python runtime.

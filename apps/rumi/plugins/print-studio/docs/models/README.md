# Model files and revisions

English | [中文](README.zh.md)

`build123d` saves exact STEP and B-Rep revisions and publishes a self-contained ASCII USD revision for the viewer. Run the CAD Python test commands below from the Print Studio package directory.

## CAD editing and USD previews

New modeling and edits use bundled `build123d` Python scripts through the existing shell tool and its permissions. Packaged Rumi includes the self-contained CAD Python runtime under `Resources/runtime/cad/cad-python`; app updates replace that runtime with the pinned release. `cad_status` uses it by default and reports a broken bundle rather than silently falling back to a separate Python installation. An explicit `cadExecutable` overrides discovery (deprecated `blenderExecutable` and `blenderHome` keys remain accepted for existing saved profiles). Development checkouts resolve `apps/rumi/.desktop-build/dev-cad/bin/python` or `cadHome/tools/cad/bin/python`; `cadHome` defaults to `DSH_RUMI_HOME` or `~/.rumi`. The bundled [cad-modeling skill](../../skills/cad-modeling/SKILL.md) owns the agent workflow; `cad_status` returns the installed `rumi_cad.py` helper and `rumi_joints.py` kit paths.

The helper works directly in **millimetres, Z up** — matching the viewer, cursor snapshots, measurements, and highlights without manual scaling. `publish(model_directory, parts, ...)` tessellates each B-Rep solid cleanly, saves immutable `model.step`, `parts/<name>.brep`, `assembly.json`, `model.usda`, and `report.json` under `models/<name>/revisions/<uuid>/`, then atomically replaces `model.usda`. Canonical USD uses metres, Z up; the helper and Three.js viewer convert automatically. Export failure leaves the previous preview intact; partial revision files remain available for diagnosis.

For undo, `helper['restore_revision'](model_directory, revision_directory_name)` validates and atomically restores an existing revision's exact self-contained USD without rebuilding geometry or deleting history. It requires the matching saved STEP/B-Rep revision files, returns their paths, and leaves the workspace scripts unchanged. Restoration reports validation pending and never confers print readiness; reload the canonical preview and use the explicit validation tools before claiming acceptance. The regression is `tests/cad-restore-revision.py`.

`viewer_load` accepts self-contained ASCII USD layers inside the project, limited to 64 MiB and 200,000 visible triangles. References, external assets, composition, variants and animation are rejected before any asset resolver runs. Publish meshes and embedded material values in one static layer. The viewer discovers `models/<name>/model.usda` before legacy entries and reloads completed exports after two identical polls. Immutable snapshot URLs preserve version identity for cursor capture and agent highlights. Invalid exports retain the last successful preview and report an error. USD parsing shares one parsed representation between metadata and geometry. Unchanged background polls reuse validated bytes after checking file identity, size and nanosecond timestamps; validation and acceptance force fresh byte reads. These checks do not establish print readiness.

`viewer_load` selects the model and wakes the viewer and waits for feedback matching the displayed URL, revision, placement, and build volume. `load.status: ready` acknowledges a visible render; `design.report` contains its measurements and `design.parameters` includes declared defaults and saved values. Build and source failures return their error, while hidden viewers, timeout, replacement, cancellation, and disposal have distinct non-ready outcomes. Timeout does not imply an unsupported model. Selection remains applied when acknowledgment fails; do not infer rollback or print readiness. Configure `viewerLoadTimeoutMs` on the Print Studio row (default 8000 ms, range 1–25000 ms).

## Legacy model migration

Store each independent preview in `models/<name>/model.usda` and preserve reproducible `build123d` source scripts under `source/`. The viewer renders USD through Three.js without executing project code. Existing STEP or B-Rep models can be imported with `helper['import_step']` or `helper['import_brep']` and republished. Legacy JavaScript entries must migrate their actual geometry into `build123d` through confined tools. No project is migrated automatically.

## CAD modeling helpers

The modeling skill supplies [solid construction defaults](../../skills/cad-modeling/SKILL.md#solid-construction-defaults) before editing: closed B-Rep solids, exact Booleans, separate-print mechanical parts, ordered filleting/chamfering, and flat resting faces. These are agent instructions, not enforced operation restrictions; CAD geometry and Bullet validation still check the results.

`cad_status` also returns `joints`, the path of `cad/rumi_joints.py`: a separate-print millimetre `build123d` modelling kit with joint recipes loaded from `cad/joints/*.py`. Each recipe creates separately printable mating features and retaining hardware (bayonet caps, snap rings, pins, clips) on the parts it is given and returns joint records plus disassembly `actions`; `K.publish` writes the STEP, B-Rep, and USD assembly in one call. The [`printable-joints` skill](../../skills/printable-joints/SKILL.md) lists every recipe with its validation status, and its `references/` cards give calls and options. Run the `tests/cad-joints.py` suite with the bundled CAD Python from this package directory for the kit regression.

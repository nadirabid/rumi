# Model validation

English | [中文](README.zh.md)

Publishing reports findings for the new revision. To investigate acceptance, follow the saved revision through geometry, printer fit and mechanical checks. Run the test commands below from the Print Studio package directory.

## Explicit validation tools

The agent follows the [modeling skill](../../skills/cad-modeling/SKILL.md#validate-a-finished-revision). `cad_status` writes the project's `.rumi/print-checks.json` from the plugin's validation settings. Every `publish` then checks the new revision in a separate CAD Python process and prints `RUMI_CHECKS <json>`: exact B-Rep solid and mesh findings, per-part print-orientation overhangs and bed contact, exact clearance findings with a nonzero count, any assembly declaration error, and the dimensions. A publish without that file prints `status: unavailable`, and a failed or timed-out check never reports a pass.

`validation_mechanics` takes a model `path`, runs any missing assembly, geometry and fit stage for the current revision, stops with that stage's findings when one has a blocking error, and otherwise runs Bullet. `validation_accept` takes the `path` and `fingerprint` that `validation_mechanics` returns.

The fingerprint captures model identity, source bytes, placement, build volume and validator policy; changed sources or placements invalidate previous stage results, and unchanged completed stage results are reused. Findings appear in tool results and `meshState.validation`; unresolved findings remain visible in the viewer. Opening or polling a preview restores validation history without starting the CAD checker or Bullet. Source, placement and printer-volume changes invalidate acceptance; explicit validation tools establish current results. Superseded checks are cancelled and drained, and completed results are reused. `validationRepairAttempts` remains accepted for existing profiles but has no effect.

Assembly inspection checks declarations and persists required movement intent. Geometry runs CAD geometry checks without clearance or Bullet. Fit checks clearance and configured printer volume and prepares the physical bodies. With no build volume, printer fit remains unchecked. Bullet requires assembly, geometry and fit results without blocking errors for the same revision and consumes the prepared bodies. The host runs these stages itself, so acceptance never rests on the agent's `publish` checks. Acceptance requires every preceding stage, complete passing mechanical coverage and preserved movement intent; it performs no simulation. Tool failures, cancellation and source changes cannot establish acceptance. Repairs are ordinary agent edits followed by another publish, not queued turns.

USD checks use immutable source snapshots with the complete parent hierarchy applied before conversion to millimetres. Legacy models require a renderer export, bounded by `validationTimeoutMs`; publish USD to avoid depending on an open viewer. Tool cancellation and shutdown kill and await children before releasing snapshots and routes. The viewer displays current models throughout checks. `validationStateDirectory` defaults to the Rumi home's `validation` directory and stores accepted originals and required movement intent atomically; unavailable or corrupt state blocks acceptance. Existing project files are not rewritten. Accepted snapshots remain recoverable after restart; explicit checks establish current acceptance again.

## Geometry and clearance

`cad/validate.py` checks immutable `.usda` and `.stl` snapshots using pure-Python/NumPy manifold, winding, intersection, degeneracy, and per-part print-orientation overhang checks, and upgrades to exact OpenCASCADE B-Rep checks (`BRepCheck_Analyzer` solid validity, `BRepExtrema_DistShapeShape` exact surface-to-surface clearance, and planar resting-face print-orientation analysis) whenever companion `.brep` files are present beside the revision. Geometry is measured in millimetres with positional welding at 0.001 mm. Configure `validation.minimumThicknessMm` (default 1), `degenerateThreshold` (0.000001), `overhangDegrees` (45), `sharpDegrees` (160), and `distortionDegrees` (45). `validationTimeoutMs` defaults to 60000. These are screening thresholds, not calibrated printer tolerances. Overhang and bed-contact findings are evaluated per part in its optimal print orientation rather than its assembled pose.

For assemblies with two or more parts, `insufficient_clearance` is an error when the surface gap between two distinct non-fixed parts is below `validation.minimumClearanceMm` (default 0.2, range 0–2, 0 disables). With B-Rep solids, `BRepExtrema_DistShapeShape` measures exact surface-to-surface distances including curved bores, and checks `fixed` mates for volumetric overlap without penalizing flush contact (`0.0 mm`). `details.pairs` lists up to eight pairs with `gapMm`, smallest first. Declared movement receives the additional checks below. Assembly, supports, material strength, and final slicer readiness are not certified. The viewer retains only input/preview-limit guards and dimension/envelope measurements.

## Mechanical validation

Models use USD Physics rigid bodies, collision APIs and fixed, revolute or prismatic joints. The default prim applies `IsaacRobotAPI`; ordered `isaac:physics:robotLinks` and `isaac:physics:robotJoints` relationships enumerate every mesh and joint. Links apply `IsaacLinkAPI`, joints apply `IsaacJointAPI`, and the first link is the fixed test root. Standard body relationships, local frames and limits define expected movement; every link must connect to the root. Revolute limits use degrees and prismatic limits use metres. Frames must meet at the saved rest pose and moving axes must agree. Required finite ranges describe coverage, not physical end stops. `rumi:control`, `rumi:retainer`, `rumi:manufacturingMode`, `rumi:sequences` and `rumi:disassembly` carry Rumi-specific UI, retainer, and manufacturing requirements. Recorded movement intent survives revisions and restarts; deleting a required control or narrowing its range cannot hide a failed check. See [physical movement declarations](../../skills/cad-modeling/SKILL.md#declare-physical-movement).

After CAD geometry checks find no blocking errors, the host passes the evaluated physical meshes and assembly to the bundled Bullet helper using protocol 2. Double-precision GImpact contacts preserve concave geometry. Only the declared root is held; every other part, including retaining hardware, remains dynamic. Fixed, revolute and prismatic connections describe expected relative behavior without creating ideal joints. Fixed connections accept an optional `retainer` (`rigid`, `snap`, `bayonet`, `threaded`, or `friction`): `bayonet` and `threaded` run axial pull-out, radial shear, and off-axis tilt probes while skipping pure unscrewing torque about the lock axis; `friction` emits `retainer_unverified_friction`. Generic probes challenge forbidden movement and force-drive permitted movement through sampled poses, monitoring every connection and collision pair.

Contact failures (`initial_interference`, `excessive_penetration`, `assembly_path_interference`) report the two assembly part IDs, penetration depth and contact position of the deepest overlap at the first failing sample. The position is the midpoint of the two contact points in placed assembly coordinates. Removal-path failures also report the moving part's sampled translation or action step from its saved pose. Depth, position and translation are in millimetres.

Retention tests escape, not tightness: a part may move through its play and passes when its connector geometry stops it within `mechanics.retentionTravelMm` (default 2, range 0.1–10) of pivot travel and `mechanics.retentionTiltDegrees` (default 15, range 1–45) of tilt. `unstable_at_rest` and `unretained_part` report a part that travels past either bound, or is still travelling outward when a retention probe ends. `linearToleranceMm` and `angularToleranceDegrees` decide only whether a driven joint reached its target (`movement_blocked`) and `movement_below_tolerance`.

Reports record part, connection and sequence coverage and the resolved simulation policy. Errors return to the calling tool; unsupported physics and incomplete coverage remain unverified. Missing executables, timeouts and malformed reports cannot pass. `mechanics.maxTotalSteps` defaults to 2,000,000 (configurable from 1,000 to 10,000,000); exceeding it leaves assemblies unverified; baseline attachment checks still report defects before full movement is skipped.

Assemblies contain at most 128 physical parts and 128 connections. Grouping disconnected solids into one mesh does not supply a physical attachment. `cad/robot_usd.py` authors the self-contained ASCII USD with Isaac annotations directly without requiring Isaac Sim or OpenUSD binary bindings. These annotations describe intended behavior; Bullet probes whether the mesh geometry realizes it. Unsupported graph coupling, deformable connections and numerical uncertainty require review. `rumi:disassembly` supports both legacy translation `path` arrays and v2 `actions` (`translate`, `rotate` with optional helical `pitchMm`, and bounded elastic `snap` with `maxInterferenceMm`).

`bulletExecutable` selects an explicit development override; packaged Rumi uses its bundled helper without searching `PATH`. `mechanicsTimeoutMs` defaults to 600000 (ten minutes), independently limiting wall time. `mechanics.retentionWorkers` defaults to 4 (1–4): after baseline checks pass, independent retention loads run in bounded parallel batches with private collision shapes. Movement steps remain sequential; findings retain serial order and every connection is still monitored.

Independent retention loads for every connection run at the saved pose and at each range-endpoint pose; intermediate movement samples and the return move probe only the moved connection. For sequences, every connection is probed at the last waypoint and only the driven connections at intermediate waypoints. No probes are omitted based on apparent symmetry or distance.

Native reports are bounded to 8 MiB. Agent context and tool results count passing probes and retain all failed or inconclusive probes, coverage and policy; the viewer state retains full diagnostic reports.

The `mechanics` profile configures density, force/torque limits, durations, integration, contact tolerance, gravity, friction and sampling. Defaults include gravity `[0,0,-9.81]` m/s², friction `0.2`, movement samples every 30 degrees or 2 mm, `probeDurationSeconds` 0.25, strict static/route `initialPenetrationMm` 0.15, dynamic GImpact `maxPenetrationMm` 0.45, `assemblySampleMm` 0.2, and `assemblySampleDegrees` 5. These are screening assumptions, not calibrated printer or material properties. A pass covers the reported finite probes; it does not certify continuous collision freedom, every simultaneous configuration, support removal, strength, wear, deformation or slicer readiness. `printReady` remains false.

## Verification

Run `tests/cad-validation.py` and `tests/cad-publish-checks.py` with the bundled CAD Python from this package directory for the B-Rep geometry and publish-time regressions. The session tests cover the mechanics tool running its prerequisite stages, revision caching, stale results, cancellation and failures. Packaging additionally dispatches both tools through the composed Host profile and project-isolation policy against real solid and moving-wheel fixtures, including CAD validation, Bullet, acceptance, cached results, cross-project denial, stale-revision rejection and a single recorded tool-calling turn. See [installed validation qualification](../../../../tests/README.md#validation-tool-qualification).

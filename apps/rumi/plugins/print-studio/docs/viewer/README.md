# Mesh preview and selection

English | [中文](README.zh.md)

The Three.js viewer loads published USD models and converts imported STL geometry to USD for display. Each conversation owns its preview. Run the highlight performance diagnostic from the repository root.

## Editable Three.js models

`viewer_transform` applies uniform scale, XYZ rotation in degrees, and bottom-centre position in millimetres without changing source. `viewer_camera` frames the design from an azimuth and elevation and returns the model identity and camera angles. Both operate on the loaded design as a whole; edit named parts in source. Camera state and placement survive successful rebuilds. Failed imports or builds leave the last successful model visible and show an error; the `meshState` runtime context includes the source revision, build error, and renderer-reported measurements. Measurements require the preview to be mounted and never certify print readiness. The existing STL import and scene tools remain available separately.

Each conversation owns its live preview. Opening a project requests its state immediately; passive polling pauses in the gallery and while the document is hidden, and resumes immediately when visible. The last selected entry and plate dimensions are saved atomically in the project’s `.rumi-viewer.json` and restored when a preview opens after restart; without a saved selection, the first discovered model opens.

Switching models refreshes the preview as soon as the host accepts the selection, without waiting for the periodic poll, and resets camera and placement. A missing or unreadable saved entry shows an error instead of substituting another model; select an available model to recover. Discovery excludes symlinked folders and entries. Only the selected source is loaded; other model files remain on disk. STL scene objects remain in memory.

Source loading and snapshots are Cordis effects owned by the Print Studio plugin. Snapshot effects collect the route registrations’ exact disposers. Unloading stops source polling, awaits admitted loads and polls, and releases routes; the viewer discards late imports and disposes its GPU resources. Orbit controls disconnect before the canvas leaves its document. Scene eviction releases the corresponding validation state; active checks retain their scene until completion. Tests exercise these paths with real Cordis contexts.

## STL scene objects

Each scene object places a shared mesh datablock. Scale and rotation use the mesh centre. Position places its bottom centre on the plate. Opening the same file twice creates two placements of one mesh. Commands return a new scene document, so earlier documents retain the undo history. The bake and measurement paths apply the same placement transform. Imports accept up to 20 MiB and 200,000 triangles. Up to eight conversations retain scenes in memory until eviction or plugin unload.

`GET /api/print-studio/viewer/state?sessionId=…` returns the scene as the browser draws it (one placement matrix per object, statuses, and counts). `GET /api/print-studio/viewer/model?sessionId=…&datablockId=…` returns one datablock's bytes, which never change once opened and are cached as immutable.

## Live model context

Print Studio maintains viewer state as selection, source, measurements, highlights, and shape controls change. Its required `rumi:mesh-state` context provider synchronously reads that state before each model attempt, including retries; it performs no file discovery or viewer operation. The snapshot includes the complete scene report and working models. Before the viewer initializes, it reports `viewer_not_initialized` rather than claiming an empty scene. Model discovery and source polling remain viewer-owned. State changes alone do not wake the agent.

Rumi keeps runtime-context snapshots append-only through the harness's `RuntimeContextProjection`: unchanged requests reuse the exact prior prompt prefix for provider KV caching, and state changes (including during retries or after compaction) append a fresh superseding snapshot without rewriting earlier history. The `mesh_state` tool is not registered. Tools validate revision identity when acting because viewer state can change during model generation.

## Model selection and agent work

The selected model is the user's browsing state. A small green dot on a model selector button identifies the agent's declared work independently of selection; its accessible name explains the dot. The `viewer_working_model` tool validates a discovered model entry, sets or clears the declaration, and never switches the preview. Concurrent agents may identify different models. Idle, cancellation settling to idle, agent disposal, and plugin disposal clear their indicators. Selected-model placement, highlighting, and shaping reject a selection that conflicts with the declared work target. A declaration reports intent; it does not verify which files a shell command edits.

The required `rumi:model-focus` runtime context uses `ctx.systemPrompt.context` and is recorded by the agent loop. It includes current selection, available models, the agent's work target, and message-ID-linked selections captured when human requests enter the inbox. Queued requests retain their individual references even if the user browses elsewhere. References unavailable after restart remain unknown rather than borrowing the current selection. Voice additionally records selection at the initial transcript capture alongside its pointing reference. Explicit names and geometric pointing references take precedence; selection supplies a default, browsing alone never retargets ongoing work, and conflicting intent requires clarification. Clear the work declaration before asking that clarification. New models acquire an indicator after their entry exists and the agent declares it.

## Pointing and named regions

For an editable model loaded with `viewer_load`, pass the current design revision and URL, a label and `meshPath` to `viewer_highlight`. Use the design path or the project-relative `selectedModel` as the model path. Write the ASCII or binary STL outside the watched model directory in project-relative storage. Use model-local millimetres, Z up, with part transforms applied before viewer placement. One mesh can contain disconnected surface patches. While Movement is active, overlay triangles on saved surfaces follow their corresponding assembly parts.

Rumi reads the model source, inspects rendered images from different angles, and analyzes the saved mesh when it creates or refreshes feature names. `viewer_analyze_surfaces` lists the parts and connected surfaces selectable by the Surface cursor. A named physical feature can cover some triangles of one surface, several surfaces or whole parts. An outline or a point such as a hinge pivot can have its own name. A short definition can explain a new term, and aliases let people use familiar words. Rumi saves the names and locations in `model.regions.json` beside the USD. See [naming model features](../../skills/name-model-regions/SKILL.md).

A map can hold up to 256 named features for a single USD revision, identified by its SHA-256. On opening the project, Rumi checks each saved map against its model revision and resolves its surface selections on the mesh. It removes invalid maps and lists the affected models in `missingRegionMaps`. The next agent turn recreates missing maps.

Call `viewer_analyze_surfaces` with `coverage: true` to audit the saved map for unnamed triangles. A valid map can still have gaps. The overview gives total and uncovered triangle counts and areas in square millimetres, plus pages of affected parts. With `partPath`, the tool gives exact selections for uncovered patches using `surfaceIds`, `faceRanges`, or a JSON array at `faceRangesPath`. Pass the reported `sourceHash` and `regionMapKey` when paging to keep both files on the same revisions.

The cursor starts in **Named regions** when the model has saved names, and in **Local patch** otherwise. Hover over a feature to highlight it and see its name. Zoom in to reveal each level of saved detail, including surfaces that span the same width as the feature enclosing them. A smaller surface uses `parentId` to identify the named surface that contains it. Click or tap to pin the current selection while you orbit and zoom. Say or type the feature name or a saved alias to refer to it in a request. The label stays in the preview. When the request names a feature in the current region map, `modelFocus.requests` records the match and source revision.

To show a saved feature in teal, pass its name, ID or alias as `viewer_highlight.region` with the current model identity. The viewer draws the same location it uses for Named regions mode. For a custom STL overlay, `regionName` supplies its own label. Measurements, exports and covers exclude overlays. An empty `meshPath`, a source revision change, or model replacement clears the overlay. Only `rendered` confirms that the visible viewer drew it.

`viewer_cursor_snapshot` captures the pin or current hover in a geometry cursor mode in the calling conversation’s preview. A mounted preview can capture a pin while the window is hidden. The result includes a PNG, capture time, camera and model identity. The image preserves the viewport’s framing at up to 1,600 pixels on its longest edge and reduces resolution when necessary to fit the upload limit. A cursor hit on a mesh includes its part path, triangle index and point. In Named regions mode, the result gives `named_regions` as the reason pointing is unavailable. While previewing a joint, `region.modelLocalPoint` locates the saved surface while the world-space point follows the posed part.

When the capture includes selected triangles from an editable model, `mesh.path` is the project-relative path to a binary STL in `.rumi/cursor-selections`, and `mesh.triangleCount` reports the number of exported triangles. The STL uses model-local millimetres, Z up, with part transforms in the saved pose and before viewer placement. To show the person's selection in teal, pass the exported path unchanged as `viewer_highlight.meshPath` after checking `identity.design` against the current model. If the export is unavailable, `meshUnavailable` reports `unsupported_model`, `empty_selection`, `geometry_unavailable`, or `storage_failed`. The image and cursor details remain available for inspection.

Only requested captures cross to the host. Live Voice requests one at the first transcript chunk since its preceding delegation and records the timestamped result and any image in separate background context linked to the spoken message ID. The user’s voice bubble contains only their words. This approximates pointing during speech; it is not audio-onset sampling. The agent must use that attached reference for the utterance rather than substitute a later cursor position. Viewer wakeups also deliver highlight changes without waiting for the two-second scene poll. The tool's structured result and durable image attachment enter the normal conversation log, making the agent's visual input replayable.

Missing intersections report `no_hit`. An unavailable capture returns `viewer_unavailable` with a reason such as a closed preview, hidden window without a pin, active temporary edit, moved preview pose, or print layout. An unanswered request reports `response_timeout` after eight seconds. Changed source/placement identities report `stale_view`, capture or image-storage failures report `capture_failed`, and a concurrent request reports `busy`. Cancellation, scene eviction, and plugin disposal release pending requests.

Responses are session/request scoped and validated before entering tool output. Images are limited to a 960-pixel longest edge and three million encoded characters; the attachment service validates and stores their PNG bytes. Agent highlights remain independently controlled by `viewer_highlight` and do not move with the cursor.

## Cursor selection

Click the 3D preview to pin the selection. Click anywhere in the preview canvas again to release it and resume hover. The selection stays pinned while you orbit, zoom, or move the pointer out of the preview. Local patch, Surface, Whole part and Edge use the geometry around the hit point. Named regions uses saved feature locations and labels. A model or placement change clears the pin.

The cursor clips its Gaussian patch to the pointed mesh and a connected surface. Surfaces stop at open edges, material seams and creases of at least 35 degrees; they are geometric regions, not semantic anatomy. The local controls select a patch, full surface, whole mesh part, or nearby boundary edge. They share the model selector’s rounded glass material, with an inset selected segment and visible keyboard focus.

Surface exports every triangle in the selected connected surface. Whole part exports every triangle in the selected mesh. Local patch exports the selected surface triangles touched by the nonzero patch. Edge exports the selected surface triangles with boundary edges touched by that patch. Local patch and Edge exports preserve whole triangles, so the exported STL can extend beyond the visible tint.

The viewer builds geometry-local face-block bounds and surface attributes once per display copy; pointer movement updates uniforms at most once per frame without model calls, host requests, geometry uploads, or flood fills. Index preparation happens when a model loads; it is not included in steady-state picking latency.

Cursor modes sit in a compact glass pill at the bottom left. With a mouse or trackpad, only the active mode is visible until hover or keyboard focus reveals the choices. Touch controls stay expanded with 44px targets. Named regions requires a region map. Reduced transparency and increased contrast use an opaque background.

## Highlight diagnostics

`viewerDiagnosticsDirectory` defaults to `~/.rumi/viewer-logs`. Private JSONL files record highlight request IDs, host wakeups and state delivery, client apply and feedback phases, document visibility, viewport dimensions, identity comparisons, and settlement latency. Client durations use a monotonic clock; host receipt times establish cross-process order. No model source, images, audio, transcript text, or credentials are recorded. Files remain until deleted. Journal I/O errors fail the owning operation; failed client trace delivery also reports to the browser console.

`not_rendered` includes `reason`: `ack_timeout` means no matching acknowledgment arrived and does not establish that the highlight was absent; `viewer_hidden` and `render_failed` are explicit renderer reports. Returning a hidden document to view redraws and reports the current highlight. A highlight-only update reuses the geometry, materials, and measurement report; only region uniforms change. Placement, volume, and source changes invalidate measurements. The CPU diagnostic `node --import tsx/esm apps/rumi/plugins/print-studio/tests/viewer-highlight.perf.ts` compares uniform updates with `--rebuild`; it excludes network, model response, and GPU time.

## Rendering during edits and checks

The viewer signals active agent work with a continuous teal surface sheen and model validation with a brighter scan that travels up and down the model. These effects use existing display geometry and one shared animation clock, draw at most 30 times per second, pause when hidden or offscreen, and remain still with Reduce Motion. Editing, model selection and print actions are disabled during work; camera orbit, zoom, precise pointing and returning to the model remain available. Work effects do not appear in project covers or alter model geometry. Validation results use the existing compact status indicator rather than a persistent text banner.

Print previews borrow original geometry and materials, suspend hover overlays without discarding their prepared indexes, and coalesce drag drawing to one animation frame. Closing, replacing the source or disposing the viewer releases preview resources before their source model. The hover index uses compact face blocks with bounded storage while retaining exact triangles and material seams. Owner-local [performance measurements](../../tests/viewer-hover.perf-results.json) cover CPU preparation, picking, and overlay suspension; they do not measure GPU frame time or end-to-end browser input latency.
